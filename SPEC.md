# evoforce — Project Specification
## Overview
evoforce is a **real-time** grid-combat game for desktop, inspired by *Mega Man Battle Network*. Two characters fight on opposite halves of an 8×4 panel grid (player cols 0–3, enemy cols 4–7). Built with [libGDX](https://libgdx.com/) (Java) targeting the LWJGL3 desktop backend.
Combat is real-time. There is no turn timer; the staging menu can be opened at any time — a **`ManaPool`** is the budget limiting how much you can stage (skills carry a `manaCost` checked against the bar), and per-skill cooldowns gate which skills are available to stage or fire. Committing drains the whole bar; cancelling drains half.
## Tech Stack
- **Language:** Java 25
- **Framework:** libGDX 1.14.0 (uses 2D `SpriteBatch` for entities/skills and 3D `g3d.ModelBatch`+`Environment` for the cave background)
- **Post-FX:** `gdx-vfx` 0.5.4 (`VfxManager` + `BloomEffect`)
- **Desktop backend:** LWJGL3 3.4.1
- **Build tool:** Gradle (wrapper included)
- **Asset tooling:** Python 3 scripts (Pillow)

## Architecture Notes
### Big picture
- **Pragmatic component-style**, not a real ECS. Ashley (and box2d/box2dlights/bullet/gdx-ai) sit on the classpath unused — don't reach for them. `Player` and `Enemy` are concrete classes that both **implement `Combatant` + `SceneRenderable`** and compose role components from `components/` (`Caster` — `SkillDeck`/`SkillSlots`/`basicAttack`/`team`/`InputLock`/`TraitsContainer`; `GridPosition` — logical `col`/`row`; `Health` — current/max HP; `Stats` — power/magic/vitality/defense/speed) plus a per-entity `StatusContainer` (in `systems/combat/`) and an `AnimController` (in `animation/` — pose state, *logical* visual position, tile-to-tile move tween, hurt strobe, death fade). Small helpers (`InputLock`, `PanelGenerator`) live in `util/`. New behavior either composes another component or is added under `systems/` (top-level — `Encounter`, `BattleState`, `CombatSystem`, `MovementSystem`, `SpawnSystem`, `ai/EnemyAi`) or `systems/combat/` (combat-pipeline — `DamageSystem`, `TriggerBus`, statuses).
- **`Combatant` interface is the skill-side handle on an entity.** Every `SkillInstance` operates on a `Combatant`, not on `Player`/`Enemy` directly — so the same skill code aims at either team. `Combatant` exposes the component getters (`getHealth`, `getStats`, `getCaster`, `getGridPosition`, `getGridMovement`, `getTeam`, `getStatusContainer`, `getAnimController`), the position shortcuts (`getCol/Row`, `getVisualCol/Row` — continuous, fractional mid-step), the action gates (`canAct`, `canStartAttack`, `canStartCast`, `canUse(skill)`), and `hittableAt(col, row)` (default: unhittable during the first half of a move tween, then hittable at the destination). There are no lifecycle callbacks — the damage pipeline drives reactions through the `AnimController` (`enterHurt()` on damage, `enterDeath()` at 0 HP).
- **HP only mutates through `DamageSystem`.** Direct `Health.damage(...)`/`heal(...)` calls live only inside `DamageSystem`. Every skill, status DoT, and panel hazard fans through `DamageSystem.apply(DamageEvent)` / `.heal(HealEvent)`, which applies defense, fires the `ON_DAMAGE_TAKEN_PRE` trigger (shields zero damage here), mutates HP, then fires `ON_DAMAGE_TAKEN`/`ON_HIT_LAND`/`ON_DEATH`/`ON_KILL` in order.
- **Status effects are uniform across player and enemy.** Each `Combatant` owns a `StatusContainer` keyed by `StatusType`. A skill applies `APPLY_STATUS` → the container holds a `Status` instance which ticks every frame (DoT/HoT via `onTick`), exposes `blocksMovement/Attack/Casting` flags consulted by movement input + AI, and can subscribe to the `TriggerBus` in `onApply` for reactive effects (`ShieldStatus` is the canonical example).
- **State machine** at the `GameScreen` level: `PlayState` ↔ `SkillSelectState`, both implementing `GameScreenState` (under `screens/state/`). `GameScreen` owns the HUDs **and the `Encounter`** (both states and the HUDs read it), and reads the run off `Main.session`; the `SkillLibrary` and persistent player loadout live on `GameSession` (in `sessions/`), not on `GameScreen`. Per-caster state (`SkillDeck`, `SkillSlots`, `basicAttack`, position, HP, stats, statuses) lives on the entity's components. States own *transient* per-frame logic and assets they alone need.
- **Run-level state lives on `Main.session` (`GameSession`).** A run owns the `SkillLibrary` + `TraitLibrary` catalogues plus a persistent `PlayerProfile` (`Caster` + `Stats` + `ManaStats`) that survives across battles — the deck *and* the caster's `TraitsContainer` ride the profile's Caster. Mana is deliberately split: `ManaStats` (max + regen) is run-level and is what upgrades modify, while the `ManaPool` itself is built by the `Encounter` and dies with the fight, so it starts empty by construction rather than needing a reset. The battle `Player` is built *from* the profile each battle (HP refills); the overworld avatar is a separate lightweight body sharing the same identity. This is why `Player`'s constructor takes a prebuilt `Caster`/`Stats` rather than minting its own.
- **Top-level Screen flow** (peer to the in-battle state machine): `MainMenuScreen` → `OverworldScreen` → `GameScreen` (battle), then **win → `RewardScreen` → `OverworldScreen`** (straight to overworld if the reward pool is drained) / **loss → `GameOverScreen` → `OverworldScreen`** (restart). The overworld is a free-roam scene (no panels); walking the avatar into a door floor-rect launches a battle. `Main.setScreen` is overridden to dispose the predecessor via `Gdx.app.postRunnable` so any caller — including code running inside the predecessor's own `render` — can swap screens without freeing textures mid-frame.
- **State machine inside each `SkillInstance`**: every shape uses an inner `Phase` enum + `phaseTime` accumulator (e.g. `DASH_FORWARD → HIT → DASH_BACK` for Strike, `CHARGE → FIRE → FADE` for Beam, `APPEAR → ACTIVE → FADE` for Zone/Aura, etc.). Phase durations are tunable `private static final float`s at the top of each instance file.
- **3D-projected 2D (HD-2D) rendering, one environment for both scenes.** `GameEnvironment` (package `environment/`) renders a seeded procedural 3D cave (noise-displaced rock, crystal formations, fog — visual data in `CaveTheme`; fixed seed for the overworld, random per battle) via libGDX g3d `ModelBatch` + `Environment`; 2D sprites are billboards placed onto the floor. It is **grid-agnostic**: `SceneCamera` owns the camera + continuous `project(worldX, worldZ)` / `depthScale(worldZ)`; `Battlefield` owns the grid's floor placement (`floorX`/`floorZ`); battle panels are floor *decoration* added via `BattlefieldDecor`. `BattlefieldDecor` is a stateful per-battle view: it keeps each panel's `ModelInstance` and pulses an emissive glow on tiles reported covered by active skills (intensity + decay are view-local animation state, fed via `CombatSystem.collectCoveredTiles`). `RenderContext` owns the tile→screen mapping (`tileWorld(col,row)`/`tileDepthScale(row)`) over `Battlefield.floorX/floorZ` (both static) + `environment.project/depthScale`. It is deliberately **not** cached: a projection is a matrix multiply, a few dozen a frame, and the old cache is what coupled combat to `resize()`. The overworld uses the same `GameEnvironment` with no panels, projecting its avatar's continuous `FreePosition`. The battle 2D pass is captured by a `gdx-vfx` `VfxManager` and run through `BloomEffect`.
- **Entity animation runs through `AnimController`** (see *Animation* below): every combatant owns one; it holds the pose state machine *and* the visual position **in grid coordinates** — the 0.15s tile-to-tile move tween, the hurt strobe, and the death fade all live there (it absorbed the old `PositionSmoother`/`HitFlash` helpers, which no longer exist). Only `IDLE` strips exist on disk today; the other states' entry points (`enterAttack/enterMove/enterHurt/enterDeath`) are wired from skill instances, `MovementSystem`, and `DamageSystem` but fall back to the IDLE row until art lands. *Skill VFX* are separate: `Skill.vfxAnimation` (`Animation<TextureRegion>`, e.g. `ice_beam`) plus the data-driven `particles/` engine.

### Package dependency rules
The deliberate import direction, top to bottom:
```
Main                    →  screens, sessions, assets, registry, environment, particles, render
screens, screens.state  →  systems, systems.combat, environment, entities, components, sessions, ui, skills, input, registry, rewards, traits, particles, render, util
rewards                 →  skills, traits, sessions, ui, components, particles  (options wrap Skills/Traits, apply() mutates the GameSession, cards build on the ui style kit)
assets                  →  registry, components, animation  (GameAssets slices monster strips into AnimSets)
registry                →  assets, components, animation    (MonsterRegistry fetches from GameAssets; Monster declares AnimSheets)
ui                      →  skills (+effects/elements/slots), entities, traits, assets, components, particles, render, systems.combat
skills                  →  entities, components, systems, systems.combat, particles, render   (skills act on Combatants and route HP through DamageSystem)
skills.effects          →  systems.combat                   (Effect carries a StatusType payload)
systems                 →  entities, components, systems.combat, systems.spawn, environment, animation, particles, registry, render, skills
systems.spawn           →  registry                         (SpawnConfig names a Monster)
systems.combat          →  components, animation            (Combatant exposes getAnimController; DamageEvent carries the originating Skill)
particles               →  assets, entities, render, skills.elements, systems.combat
render                  →  environment                      (RenderContext bundles the GameEnvironment)
environment             →  entities                         (BattlefieldDecor reads Battlefield; SceneCamera/GameEnvironment are otherwise gdx-only)
traits                  →  skills.elements, systems.combat  (TraitEffects subscribe to the TriggerBus and route heals through DamageSystem)
sessions                →  skills, traits, components, systems, systems.spawn  (GameSession owns SkillLibrary + TraitLibrary + SpawnTable)
entities                →  components, systems, systems.combat, skills, animation, render, util
components              →  skills, traits, util, entities   (Caster imports SkillDeck + TraitsContainer; GridPosition imports Battlefield)
animation               →  (leaf — no com.silverignis imports)
util                    →  entities                         (InputLock is dependency-free; PanelGenerator reads Battlefield)
```
**`animation/` is the true leaf.** It has zero project imports, which is what lets `assets`, `registry`, `entities`, and `systems.combat` all depend on it freely. `util/` is *nearly* leaf: `InputLock` has no project imports (`lock(Object)` takes `Object` so a `SkillInstance` can hold the lock without `util` depending on `skills`; identity comparison is the contract), but `PanelGenerator` reads `Battlefield`.

**Known cycles beyond `assets ↔ registry`:** `screens ↔ Main` (screens hold the `Main` root to swap screens), `entities ↔ systems` (`BattleState` names `Player`/`Enemy`; systems drive entities), and `skills ↔ particles` (skills carry `VfxFactory` lists; `particles` reads `skills.elements`). Tolerated — each crosses the boundary for one narrow reason.

**`Team` lives in `components/`, not `entities/`.** It's read by `Caster`, by `ProjectileInstance` (for direction), and by every `BattleState` team-aware lookup. Keeping it under `components/` lets `Caster` import it without creating a `components/ → entities/` edge for an enum alone.

**`systems.combat/` is the combat-pipeline subpackage.** It holds the `Combatant` interface, `DamageSystem`, `TriggerBus`, and the `Status` hierarchy. It depends on `components/` and `animation/` (Combatant exposes `getAnimController`; DamageSystem drives hurt/death poses), plus one narrow `skills` edge: `event/DamageEvent` carries the originating `Skill`. Still no `entities/` edge, so the pipeline can be tested with fakes. The `entities → systems.combat` edge exists because `Player`/`Enemy` implement `Combatant`; the `skills → systems.combat` edge exists because `SkillInstance` operates on `Combatant`s and routes HP changes through `DamageSystem`.

**`components/ → entities/`** exists because `GridPosition` calls the static `Battlefield.floorX/floorZ`. Tolerable: `entities/Battlefield.java` is itself a leaf (pure geometry + panel state, no upward deps). If we tighten the cycle, move `Battlefield` somewhere neutral.

**`assets/ ↔ registry/` is a tolerated cycle.** `GameAssets` loads monster sprites (it iterates the `Monster` enum and calls `Monster.texturePath`), while `MonsterRegistry` fetches them back through `GameAssets` — so the two packages import each other. Accepted because the only thing crossing the boundary is the monster sprite-path convention; the alternative (a third neutral package just for `Monster`) buys little for two small classes. If it grows, move `Monster` somewhere neutral both can depend on.

**`components/` is the ECS-style role layer.** Skill-aware composable pieces live here and may freely import from `skills`. Today: `Caster`, `GridPosition`, `GridMovement`, `GridBounds`, `Direction`, `FreePosition`, `Health`, `ManaPool`, `ManaStats`, `Stats`, `Team`. `Health` and `Stats` are deliberately dumb data — all mutation logic lives in `systems/combat/DamageSystem`. Entities mostly reach skill state through the composed `Caster`, though `Player`/`Enemy` do import `skills` directly for deck/loadout setup (`setupSkills`). `GridMovement` bundles a `GridPosition` with the entity's `GridBounds`; `Direction` is the shared step-vector enum read by `MovementSystem`.

### Per-frame loop
Every frame `GameScreen.render(delta)` runs:
1. `InputManager.update()` — refresh each child source, then OR-fold their pressed states. Edge detection (`isActionJustPressed`) lives at the manager so two sources holding the same action don't double-fire.
2. `currentState.input()` — dispatch `GameAction`s to handlers.
3. `currentState.update(delta)` — game logic (see "PlayState tick order" below).
4. `currentState.render(batch)` — clear, project, draw the world.
5. HUD pass — `ManaBarHud` + `SlotsHud` + `BasicAttackHud` + `LifeBarHud` + `StatusHud` + `FpsHud` draw on top of whichever state is active. All of them except `FpsHud` are hidden while the staging overlay is up and untucked (`overlayUp` gate in `GameScreen.render`); `hudStage.act(delta)` runs before `draw()` so Scene2D actions (the status tray fades) advance.

**Tick order matters, and it lives in `Encounter.tick(delta)`:**
`player.update → each enemy.update` (per-caster cooldowns tick inside, via the composed Caster's `update → deck.update`) `→ mana.update → each EnemyAi.update → combatSystem.tickStatuses` (advance per-combatant StatusContainers — DoTs/HoTs can damage or heal here, possibly killing the owner) `→ combatSystem.update` (skill instances tick + clash resolution + finished cull).

A single `tick` suffices because libGDX runs `input()` before `update()`, so the loaded-burst release happens outside the tick entirely. (The Godot port splits this into named phases because everything there runs in one `_Process`, forcing the release *between* two phases — the two orderings genuinely differ.)

`PlayState.update` then adds the presentation tail: `encounter.tick(delta) → encounter.collectCoveredTiles(battlefieldDecor::glow) → battlefieldDecor.update` (glow decay) `→ particles.update → environment.update` (crystal pulse) `→ checkBattleOver` (early-return on win/lose) `→ tickAndCullEffects`. Entities are no longer handed a projected target each frame — visual position is logical and the render pass projects it.
Status ticks happen *between* enemy AI and skill instance updates so a status DoT that kills an enemy this frame propagates into the same frame's clash/hit checks (which test `isAlive()`). Skill instances tick *after* entity movement (so `originCol/Row` snapshotted at fire-time is still valid for that frame). The "re-project" step pushes each entity's projected screen-space target tile and depth scale into its `GridPosition` so the smoother tweens toward the right pixel and `render()` knows the perspective scale. `checkBattleOver` reads `allEnemiesDead()` (every enemy in the list past its 0.5s death fade) and `!player.isAlive()`; win transitions to `RewardScreen` (or `OverworldScreen` when the skill pool is drained), loss to `GameOverScreen(LOST)`, and either sets `transitionScheduled = true` so the transition only fires once.

### Render layering
`PlayState.render(batch)` runs two passes inside a `VfxManager` capture, then post-FX to screen:

**Pass 1 — 3D scene (`environment.render`):** `ModelBatch` draws the seeded procedural cave — noise-displaced wall/ceiling/floor meshes (the gameplay rect stays perfectly flat via a smoothstep mask), amethyst crystal formations (hero clusters at shuffled perimeter anchors, lone + hanging spires) — and the panel-grid slabs (blue on player side, red on enemy side), lit by `Environment` (themed ambient + fog + directional + 3 crystal-anchored point lights + a fixed front fill). Crystals and their light pools breathe on a slow per-cluster pulse (`environment.update(delta)`). The depth buffer is cleared afterwards so 2D never z-fights with 3D.

**Pass 2 — 2D battle (`renderWorld(batch)`), via `WorldRenderer`:** everything drawable implements `SceneRenderable` (`layer()` + `depth()` + `render(RenderContext)`). `PlayState` *submits* the player, every alive enemy (plus their shadows and HP labels), `combatSystem.submitRenderables(...)` (active skill instances), live `BattleVfx`, and the particle engine's emitters; `WorldRenderer.flush(ctx)` then draws by layer:
1. `GROUND` — zone ground effects, shadows (submit order)
2. `BILLBOARD` — entities, skill sprites, particles, one-shots — **depth-sorted back-to-front**, so a back-row caster occludes correctly regardless of how many enemies are on the field
3. `OVERLAY` — enemy HP labels and other always-on-top scraps

**Post-FX:** `VfxManager` ends capture, applies `BloomEffect` (base 1.0, bloom 1.4, threshold 0.18, saturation 0.85 — set in `Main`), and blits to screen.

**HUD pass** (`GameScreen.render`) draws `ManaBarHud`, `SlotsHud`, `BasicAttackHud`, `LifeBarHud`, `StatusHud`, and `FpsHud` on top of everything — outside the VFX capture, so HUD doesn't bloom.

`SceneRenderable.layer()` is the hook that splits draws across the three layers (`ZoneInstance` returns `GROUND` so terrain-style art sits under sprites).

### Animation
Two frame-animation systems coexist, kept **separate by design** because they solve different problems:

- **Character pose animation** — `AnimController` + `AnimSet` + `FrameClip` + `AnimState`/`AnimSheet` (package `animation/`). A per-entity state machine over `AnimState` (IDLE/MOVE/ATTACK/CAST/HURT/DEATH) with priority, interrupt, and loop/return-to-previous rules. `GameAssets.sliceAnimSet(Monster, Team)` builds one `AnimSet` per facing from per-state horizontal strips at `sprites/<monster>/<state>/<se|sw>.png` (`cell = sheet height`, frames advance left-to-right); the `(Monster, Team)` pair is fetched via `MonsterRegistry.getAnimSet`. `Player`/`Enemy` own an `AnimController`, tick it each frame, and hand its `currentFrame()` to the renderer. The controller also owns the entity's **visual position, in grid coordinates** (`getVisualCol/Row`, fractional mid-step; the render pass projects it, so a resize mid-step stays correct) — the 0.15s tile-to-tile move tween (`enterMove(fromCol,fromRow,toCol,toRow)`, driven by `MovementSystem`), the hurt strobe (`enterHurt`, 0.05s flicker via `isHurtHidden()`, HURT state locked 1.0s), and the death fade (`enterDeath`/`isDeathComplete()`) — it absorbed the old `PositionSmoother` and `HitFlash` helpers, which no longer exist. The state entry points are already called from gameplay (`StrikeInstance`/`ProjectileInstance`/`LobInstance`/`BeamInstance`/`AuraInstance` → `enterAttack`, `DamageSystem` → `enterHurt`/`enterDeath`, `MovementSystem` → `enterMove`), but today only `IDLE` is declared in `Monster.animSheet()` (7 frames @ 7 fps, loop; lionen 8 @ 8) — every other state falls back to the IDLE row until art lands (see Known Gaps).
- **Skill VFX** — `Skill.vfxAnimation` is a libGDX `Animation<TextureRegion>` (built by `SkillLoader`), drawn per-`SkillInstance` in `render(batch, ctx)` and sequenced by each shape's own phases (Strike `DASH→HIT→DASH_BACK`, Beam `CHARGE→FIRE→FADE`, …); `ClashEffect` is the generic scale+fade one-shot. These are one-shot, self-culling, and shape-specific — they do **not** go through `AnimController`.

The boundary is intentional: don't route skill VFX through the pose state machine (they have no pose states), and don't reach for a libGDX `Animation` for character poses (use `AnimSet`/`FrameClip`). The one accepted overlap is two frame-sequence primitives — `FrameClip` vs `Animation<TextureRegion>` — doing the same `frame(time)` job; unify only if it ever pays off.

### Skill execution data flow
```
PlayState.handleSlotFire
   └─ tryFireSlot(key)
        ├─ player.canStartCast() ?          → bail before popping (a refused cast must not eat the card)
        ├─ slot.pop()                       → Skill (pure data)
        └─ encounter.cast(player, skill)    → deck.onUsed + SkillFactory.create(skill, combatant) + spawn
```
- **One cast gate, two entry points.** `CombatSystem.tryCast(combatant, skill)` gates (`combatant.canUse(skill)`), starts the cooldown and spawns, returning whether it fired; `cast(...)` skips the gate for cards already filtered at staging time and popped off the slot, where re-gating would silently swallow the card. Player basic attack and enemy AI use `tryCast`; slot fires and released bursts use `cast`.
- **Three separate action gates.** Movement checks `blocksMovement` (in `MovementSystem.tryGridStep`), the basic attack checks `blocksAttack` (`canStartAttack`), and every other skill checks `blocksCasting` (`canStartCast`) — each predicate has exactly one call site. Which gate a skill uses is decided by identity: `skill == caster.getBasicAttack()` is an attack, anything else is a cast. When a deck skill needs to count as an attack, put the kind on `Skill` and switch on that.
- **Hold-to-load burst:** holding `TRIGGER_RIGHT` while pressing a slot key *loads* the popped skill into the caster's loaded-skill queue (`encounter.loadSkill`) instead of firing it; releasing the trigger fires everything loaded at once (`releaseLoadedSkills`, which walks the queue through the same `cast` path — with a `matchRecipe` stub reserved for future combo fusions).
- `Skill` is reusable, immutable data: `Shape`, `Element`, `cooldown`, ordered `List<Effect>`, mandatory `vfxTexture`, optional animation + `ShapeConfig`, plus `powerScale`/`magicScale` knobs that mix the caster's `Stats.power`/`Stats.magic` into the damage roll. Many `SkillInstance`s can run from the same `Skill`.
- `SkillInstance` owns its own state machine; subclasses override `update(delta, SkillContext)` and optionally `render(RenderContext)`. **It stores neither context** — the simulation arrives per tick, rendering per draw, so an instance cannot reach the camera while ticking nor the battle while drawing. The base class holds the firing `Combatant` (plus its `caster`/`pos` for convenience), tracks `originCol/Row` snapshotted at construction, and wires `acquireInputLock()` / `releaseInputLock()` / `finish()` boilerplate.
- Hit application goes through `applyEffectsTo(Combatant, SkillContext)` on the base class — one generic method handling `DAMAGE` (routed through `ctx.damageSystem.apply` with `powerScale/magicScale` mixed into the base value), `HEAL` (`ctx.damageSystem.heal`), `APPLY_STATUS` (rolls `chance`, then `target.getStatusContainer().apply(StatusFactory.create(...), ctx.triggerBus)`), and the reserved `KNOCKBACK`. There are no per-entity overloads — Player vs Enemy is just a flag the `DamageSystem` and `StatusContainer` honor uniformly.
- A skill instance can spawn child instances (e.g. a `LobInstance` landing spawns a `ZoneInstance` "cloud") via `ctx.combatSystem.spawn(...)`. `CombatSystem` builds its own `SkillContext` passing `this`, so that back-edge is immutable rather than a field set from outside after construction.
- One-shot visuals go into `ctx.vfxSink` **named by tile, not by screen point** — a `ClashEffect` resolves its own position when drawn, so it survives a resize. Persistent visuals stay inside the instance and draw via `CombatSystem.submitRenderables`. `vfxSink` and `particleEngine` are the last two presentation handles left in `SkillContext`; both are marked `ponytail:` and go when instances emit events instead.
- `CombatSystem.update` iterates over a snapshot index so an instance that spawns another mid-tick doesn't get double-ticked the same frame.

### Combat & status pipeline
The `systems/combat/` package is the backbone for HP changes and reactive effects. It is intentionally isolated from `entities/` and `skills/` so it can be tested with fakes.

- **`DamageSystem.apply(DamageEvent)`** is the single entry point for HP loss. Order: (1) early-out if target is null/dead or amount ≤ 0; (2) defense mitigation — `max(1, raw * 100 / (100 + defense))`; (3) `bus.fire(ON_DAMAGE_TAKEN_PRE)` — shields/parries zero `ev.amount` here; (4) `Health.damage` + `target.getAnimController().enterHurt()`; (5) `bus.fire(ON_DAMAGE_TAKEN)`, then `ON_HIT_LAND` for the attacker; (6) if HP reached 0, fire `ON_DEATH`/`ON_KILL`, then `target.getAnimController().enterDeath()` (the death fade runs on the controller; `Enemy.isDead()` reads `isDeathComplete()`).
- **`DamageSystem.heal(HealEvent)`** is the parallel path: write through `Health.heal`, fire `ON_HEAL`. Capped at `Health.max`, and **halved while the target has BURN** (burn suppresses healing).
- **`TriggerBus`** is a small pub/sub keyed on the `Trigger` enum. Listeners may filter to a specific `Combatant` so per-entity status effects (e.g. ShieldStatus on the *player*) ignore events on other targets. Dispatch snapshots the bucket so listeners can unsubscribe mid-fire.
- **`Triggers`**: `ON_HIT_LAND`, `ON_DAMAGE_TAKEN_PRE`, `ON_DAMAGE_TAKEN`, `ON_HEAL`, `ON_DEATH`, `ON_KILL`, `ON_TICK`. `TriggerEvent.combatant` is the *subject* of the trigger (attacker for `ON_HIT_LAND/ON_KILL`; target for the rest); `payload` is `DamageEvent` / `HealEvent` / `null` depending on trigger — listeners cast based on what they subscribed to.
- **`StatusContainer`** owns an `EnumMap<StatusType, Status>` per `Combatant`. `apply(status, bus)` either inserts (calling `onApply`, which is where reactive statuses subscribe to the bus) or refreshes the existing status's duration. `update(delta, dmg, bus)` snapshots the value set, ticks each, then removes any that expired. `has(StatusType)` is the read used by render code (freeze tint) and the AuraInstance fade check. `blocksMovement/Attack/Casting` are OR-folded over all live statuses and gate input + AI.
- **`Status`** base provides `remaining` countdown, optional `tickInterval` for periodic effects, and `blocksMovement/Attack/Casting` hooks. Concrete statuses:
  - `FreezeStatus` — blocks all three (movement/attack/casting); rendered as a blue sprite tint.
  - `StunStatus` — blocks movement + attack (casting is allowed).
  - `BurnStatus` / `PoisonStatus` — DoT via `dmg.apply(new DamageEvent(null, owner, dmgPerTick, STATUS, null))` every 0.5s (burn) / 1.0s (poison).
  - `RegenStatus` — HoT via `dmg.heal(new HealEvent(owner, healPerTick))` every 0.5s.
  - `ShieldStatus` — subscribes to `ON_DAMAGE_TAKEN_PRE` for its owner in `onApply`; the listener zeros `ev.amount` and self-expires (`remaining = 0`) so the next status tick fires `onExpire` (which unsubscribes). One incoming hit → shield consumed; otherwise expires by duration.
  - `PowerUpStatus` / `MagicUpStatus` — timed buffs that triple the owner's power/magic for the duration (this is where `power_up`/`magic_up`'s "triple" lives — it's not in the skill data).
- **`StatusFactory.create(type, duration, dotMag)`** is the `Skill` → `Status` bridge. `dotMag` is the per-tick value (damage for Burn/Poison, heal for Regen, ignored for Freeze/Stun/Shield/PowerUp/MagicUp).
- **`Effect`** records (`DAMAGE`/`HEAL`/`APPLY_STATUS`/`KNOCKBACK`) are pure data on a `Skill`. `APPLY_STATUS` carries `statusType` + `duration` + `chance` + `value` (which becomes `dotMag` for DoT/HoT statuses).

### Input pipeline
- `InputSource` is the unified pollable interface (`isActionPressed`, `isActionJustPressed`, `update`).
- `KeyboardInputSource` keeps no internal state: it forwards both queries to `Gdx.input.isKey{Pressed,JustPressed}` and lets libGDX manage edges.
- `GamepadInputSource` *does* keep its own current/previous maps because gdx-controllers is event-driven (`buttonDown`/`buttonUp`/`axisMoved` callbacks). Trigger axes are thresholded (`> 0.5`) into booleans because L2/R2 arrive as analog values.
- `InputManager` composes any number of sources, ORs their pressed state per `GameAction`, and runs *its own* edge detection on the OR-folded result. This is the layer that prevents double-fires when both keyboard and pad are pushing the same action.

### Resource ownership & disposal
GPU resources have **four central owners**, loaded once and disposed once; everything else *borrows* and never disposes what it borrows:

- **`GameAssets` (package `assets/`, owned by `Main`)** wraps a single libGDX `AssetManager` and owns every file-loaded texture: cave wall/floor, the **particle effect sheets** (16 texture sets — SPARK/STAR/SMOKE/CIRCLE/FLARE/FLAME/MAGIC/LIGHT/SYMBOL/TWIRL plus `_a` variants — consumed by the `particles/` engine), **and all monster animation strips** (every declared `(state, facing)` for every `Monster`, sliced in `finishLoading` into `(Monster, Team)`-keyed `AnimSet`s). No audio is loaded today (the `sound()`/`music()` facades exist with nothing queued), and the overworld avatar isn't a file — it's derived from BEASTKIN's IDLE frame 0. `Main.create()` runs `assets.queueLoad()` then `assets.finishLoading()` (synchronous — `get()` is two-phase, never lazy, so the roster must be known up front; structured so an async loading screen could replace `finishLoading()` later). A typed facade (`caveWall()`, `avatar()`, `texture(path)`, …) hands shared instances to callers. `assets.dispose()` frees the whole manager at once.
- **`GeneratedAssets` (package `assets/`, owned by `Main`)** owns the runtime-generated (Pixmap-built) textures the `AssetManager` can't manage: the shared 1×1 white `pixel()` (HUDs draw it tinted for bars/fills), the soft `shadow()` ellipse drawn under combatants, the `card`/`cardFrame` reward-card backdrops, and `caveFloorEmissive`. Built in `create()` (needs a GL context); `dispose()` frees them all.
- **`SkillLibrary` (owned by `GameSession`)** owns each skill's icon, VFX texture, and any VFX animation sheet; all disposed in `SkillLibrary.dispose()` via `GameSession.dispose()`.
- **`TraitLibrary` (owned by `GameSession`)** owns each trait's icon texture (traits have no VFX); disposed in `TraitLibrary.dispose()` via `GameSession.dispose()`. Reward cards and the staging overlay's trait tray borrow the icons.

These four sets are **disjoint** — no texture is owned twice, so there is no double-dispose. Borrowers:
- **`MonsterRegistry` (package `registry/`, owned by `Main`)** owns nothing — it's a fetch facade. `getAnimSet(monster, team)` returns the pre-sliced `AnimSet` for that facing (player → east/`_se`, enemy → west/`_sw`) from `GameAssets`. `Monster.texturePath(state, facing)` is the single source of truth for the strip path (`sprites/<monster>/<state>/<se|sw>.png`): `GameAssets.queueLoad` loads every declared `(state, facing)`, and `finishLoading` slices them into `(Monster, Team)`-keyed `AnimSet`s. Each entity builds its own `AnimController` from the fetched `AnimSet` (the controller carries per-instance state/time, so combatants can't share one).
- **`GameEnvironment`** (owned by `Main`, shared by `OverworldScreen` and `PlayState`) borrows the cave wall/floor textures (passed in via `CaveTheme` from `GameAssets`); it owns only its `ModelBatch` and the `Model`s it builds. `rebuild(seed)` disposes and clears only those owned `Model`s (never the decor arrays — the previous screen's deferred `clearDecor()` runs *after* the next screen's constructor because `Main.setScreen` disposes via `postRunnable`).
- **`VfxManager` + `BloomEffect`** are owned by `Main` and shared across screens — both `PlayState` and `OverworldScreen` wrap their render in `vfxManager.beginInputCapture()` / `endInputCapture()` / `applyEffects()` / `renderToScreen()` so the same bloom pass runs everywhere. `Main.resize` forwards window resizes to `vfxManager.resize`.
- **`WorldRenderer` + `RenderContext` + `ParticleEngine`** are also owned by `Main` and shared across screens (Main seeds two ambient-dust emitters at startup). All three are plain Java holding no GPU state of their own — they draw with borrowed textures — so they have no `dispose()` in `Main.dispose()`.
- **`PlayState`** borrows `GameEnvironment`, `VfxManager`, `BloomEffect`, `WorldRenderer`, and the `ParticleEngine` from `Main`, and constructs the per-battle `TriggerBus`/`DamageSystem` (plain Java, GC'd with the state). Its combatant sprites and shadow are all borrowed (`GameAssets`/`GeneratedAssets`). `PlayState.dispose()` only clears the per-battle `BattlefieldDecor` it added to the shared environment.
- **HUDs** borrow the shared `GeneratedAssets.pixel()` (constructor-injected) — most own no textures and have no `dispose()`. GPU-resource owners: `SkillSelectOverlay` (its Scene2D `Stage`, FreeType fonts, and a `RoundedRectShader`; disposed via `SkillSelectState.dispose()`); `GameScreen` (the HUD `Stage` and the one `RoundedRectShader` shared by `SlotsHud`/`LifeBarHud`/`ManaBarHud`); `SlotsHud` (its FreeType key font; `GameScreen.dispose()` calls its `dispose()`). `Battlefield` and `StatusContainer`s likewise hold no GPU resources.
- **`Main.dispose()`** frees `session` (→ `SkillLibrary`), `batch`, `font`, the active `screen`, then `generated`, `bloomEffect`, `vfxManager`, `environment`, and `assets`. `GameScreen.dispose()` only cascades into `playState` + `skillSelectState`.
- **Cross-screen disposal is centralized in `Main.setScreen`.** The override captures the outgoing screen, calls `super.setScreen(...)` (which fires `hide` on the old and `show`/`resize` on the new), then schedules `old.dispose()` via `Gdx.app.postRunnable`. Deferring to the next frame avoids the mid-render hazard where a screen's own `render()` call stack is still unwinding when `setScreen` is invoked. Individual screens therefore do **not** self-dispose after `setScreen`.

**Don't add `new Texture(...)` calls inside per-frame paths, and don't load files outside `GameAssets`.** File textures go through `GameAssets.queueLoad`; procedural textures live in `GeneratedAssets`. The shadow is the canonical procedural example — built once in `GeneratedAssets` and reused every frame.
## Core Classes
### `Main` (extends `Game`)
Application root. Owns shared rendering resources (`SpriteBatch batch`, `BitmapFont font`, `FitViewport viewport` — 16×9, plus the shared `WorldRenderer`/`RenderContext`/`ParticleEngine` and the `VfxManager` + `BloomEffect` post-FX pair) plus the central asset layer: `GameAssets` (the single `AssetManager` wrapper — `create()` runs `queueLoad()` + `finishLoading()`), `GeneratedAssets` (shared Pixmap-built textures, built once GL is up), and `MonsterRegistry` (sprite fetch facade over `GameAssets`). `create()` pushes `MainMenuScreen` and seeds the ambient dust emitters. Overrides `setScreen(Screen)` to dispose the predecessor via `Gdx.app.postRunnable` — see "Resource ownership & disposal" above.
### Screens
- **`MainMenuScreen`** — splash; switches to `OverworldScreen` on touch (`Gdx.input.isTouched()` — touch/click only, no `InputManager`, no keyboard/controller support).
- **`GameScreen`** — owns the HUDs (`ManaBarHud`, `SlotsHud`, `BasicAttackHud`, `LifeBarHud`, `StatusHud`, `FpsHud`) **and the `Encounter`** — it builds the `Player` and the enemy roster, then calls `Encounter.create(...)`. The encounter lives here rather than on `PlayState` because `SkillSelectState` and the HUDs read it too (`encounter.mana()`). Per-caster state (`SkillDeck`, `SkillSlots`, the basic-attack holder) lives on the `Caster`, not here — seeded once per run by `PlayerProfile` (starter deck of six: `wind_strike`/`fire_blast`/`heal`/`ice_beam`/`shield`/`electro_ball`; `wind_slash` assigned as the basic attack, fired via the dedicated `ATTACK_BASIC` button, so it deliberately stays out of the staging hand). The deck grows only through the post-win `RewardScreen`. Delegates per-frame `input/update/render` to whichever `GameScreenState` is active; the HUD pass draws on top of the state's rendering.
- **`GameOverScreen`** — post-battle "YOU WON" / "YOU LOST" overlay shown on a solid black backdrop. Constructed with a `Result { WON, LOST }` (only the loss path reaches it today — wins go to `RewardScreen`). Owns its own `InputManager` (default keyboard + gamepad). Restarts on `SKILL_SELECT_CONFIRM` (Enter or A) by calling `Main.setScreen(new GameScreen(...))`; the override disposes the spent `GameOverScreen` next frame.
- **`RewardScreen`** — post-win reward chain with a reveal ceremony. Constructed with a `List<RewardOffer>`; `buildOffer()` runs **once per offer**: title/counter/card row/hint plus a `ParticleLayer` actor, resetting `Channel.MENU` and starting the `rewardAmbience` particle bed over an arcane-blue backdrop. Each card then plays a staggered (0.35s apart) reveal: spiral-in gather arms + glyphs + a magic-circle pop, a `TraceBorder` tracing the frame outline (from 0.5s, over 0.6s), then the frame materializes at 1.1s (fade-in + swingOut scale) with a rim `revealBurst`. Any input during the ceremony **fast-forwards** (`timeScale = 3` on both particles and stage) rather than skipping; input is otherwise swallowed until `finishCeremony` attaches mana wisps over every card face. After that, ←/→ moves the highlight (`applySelection` swaps `RewardCardStyle.cardBg`/`cardBgSelected` and restarts the selection wisps — no stage rebuild), `SKILL_SELECT_CONFIRM` applies the selected `RewardOption` to `game.session` and `exitOffer` plays a confirm burst + punch-out while the unchosen cards fade away, `SKILL_SELECT_CANCEL` skips the offer. `advance()` moves to the next offer or lands on `OverworldScreen`. Each option still builds its own card content via `buildContents(style)` — no type switches. Owns and disposes its `Stage` + `RewardCardStyle`; skill icons stay `SkillLibrary`-owned.
### States
- **`PlayState`** — real-time combat. Reads movement (WASD), basic attack (J), slot fire (1/2/3), and the `Q+E` trigger combo to open the staging menu (no gate — mana prices what you stage, not when you may look). Holding `TRIGGER_RIGHT` (E) while pressing a slot key *loads* the skill instead of firing it; releasing the trigger fires every loaded skill at once (`resolveLoadedSkills` — see the hold-to-load note under *Skill execution data flow*). Reads `screen.encounter` — it constructs nothing about the battle itself, only the presentation around it (the `Battlefield` panel grid, `BattlefieldDecor`, shadow and HP-label views). Slot pops go through `player.getSlots()`; every cast routes through `encounter.tryCast`/`cast`. Per-caster cooldowns tick inside `<entity>.update → caster.update → deck.update`; mana regen is inside `Encounter.tick`, so mana is frozen while the menu is open (the encounter stops ticking). `checkBattleOver` reads `encounter.outcome()` and reacts: `VICTORY` → `progressPlayer()` then `RewardScreen` (skill + trait offer queue; `OverworldScreen` when both pools are drained), `DEFEAT` → `GameOverScreen(LOST)`. Both paths call `encounter.finish()` + `encounter.resetStaging()`, and a `transitionScheduled` flag prevents repeated transitions during the one-frame gap before disposal fires.
- **`SkillSelectState`** — staging menu. `onEnter()` snapshots `player.getSlots()`, draws a hand of 6 via `player.getDeck().drawHand(HAND_SIZE, player.getSlots())` (filtered by deck cooldowns + slots already loaded). Focus is a four-zone spatial model (`Zone { HAND, DETAIL, STACKS, OPERATOR }`): `MOVE_UP/DOWN` walks the left column hand → detail → operator; `MOVE_LEFT/RIGHT` from detail/operator jumps to the stacks on the right (and LEFT off the stacks' first slot returns to detail); within hand/stacks LEFT/RIGHT moves the card cursor. `SKILL_X/Y/B` assign the highlighted card to that slot — refused if its `manaCost` would push the running `pendingCost` past current mana. Skills present in the snapshot are *prepaid*: they stage for free and refund nothing on undo (`isPrepaid`). `Enter` confirms staging from hand/stacks (spends `pendingCost`); on the operator panel it instead opens the **trait tray** — a modal (chip grid + tooltip, built by `SkillSelectOverlay.buildTraitTray`) whose input block sits first in `input()` and swallows everything except LEFT/RIGHT chip navigation and confirm/cancel-to-close, so closing the tray can never trigger the cancel mana forfeit. `Esc`/`Back` in a zone cancels staging (slots restored from snapshot, **entire mana pool forfeited** — backing out is punished). **Undo** (`SKILL_SELECT_UNDO`, Backspace / L1): every assign pushes its `SlotKey` onto a LIFO `selectHistory`; from HAND/DETAIL, undo pops the most recent assignment's slot top back into the hand (refunding its `pendingCost` unless prepaid); from STACKS it targets the slot under the cursor instead (removing that key's history entry) — no-op on the operator panel. **Tuck** (`SKILL_SELECT_TUCK`, Tab / R1) toggles a view-only mode that hides the overlay and ignores all other input, for peeking at the frozen field. Confirm and cancel both play an exit animation (`overlay.confirmFlourish` / `overlay.onHide`) before returning to `PlayState`; an `exiting` flag gates input meanwhile. Renders the world frozen behind the overlay.
### Entities
- **`Battlefield`** — `COLS=8 × ROWS=4` grid of `PanelType` enum values. Cols 0–3 are player territory, cols 4–7 enemy. Panel types: `NORMAL_BLUE`, `NORMAL_RED`, `CRACKED`, `BROKEN`, `ICE`, `LAVA`, `GRASS`, `POISON`. `PanelGenerator` has two factories: `generatePanels()` (default flat blue/red split, used today) and `generateMixedPanels()` (sprinkles hazard tiles — useful for testing once panel effects are wired).
- **`Player`** — `implements Combatant, SceneRenderable`. Composes `Caster(Team.PLAYER)`, `GridMovement` (`GridPosition` + `GridBounds(0, COLS/2-1, …)` — the half-grid clamp is enforced centrally by `MovementSystem.tryGridStep`, not by entity methods), `Health` (max HP = `Stats.vitality`, 100 today), `Stats`, a `StatusContainer`, and an `AnimController`. `MovementSystem.tryGridStep` early-outs if `caster.getInputLock().isLocked()` OR `statusContainer.blocksMovement()` — so freeze/stun gate movement uniformly with skill locks. `getCol/Row` delegate to `GridPosition`; `getVisualCol/Row` read the `AnimController`'s continuous grid position (fractional mid-step; the render pass projects it); `getTeam/InputLock/Deck/Slots/BasicAttack` delegate to `Caster`; `getHp/getMaxHp` read through `Health`. The post-hit invisible-frame flicker is the controller's hurt strobe (`enterHurt`, 0.05s flicker; HURT holds 1.0s). `update(delta)` ticks `caster.update` + `animController.update`. Skill dashes drive the body via `MovementSystem.forceGridTeleport` (clamped only to the global grid edge) so `StrikeInstance` can enter enemy territory mid-skill. HP mutation happens exclusively through `DamageSystem`. **No bespoke basic-attack code** — pressing `ATTACK_BASIC` fires the `Skill` held in `getBasicAttack()` through the standard `SkillFactory` + `CombatSystem` pipeline (the same one slot fires use), gated by `getDeck()`'s cooldown map.
- **`Enemy`** — `implements Combatant, SceneRenderable`. Same composition (`Caster(Team.ENEMY)` + `GridMovement` + `Health` + `Stats` + `StatusContainer` + `AnimController`), constrained to cols 4–7; stats, deck skills, and the basic attack are injected from its `SpawnConfig` via `setupSkills` (see `SpawnSystem`). Movement AI: `stepRandomly()` picks a random direction every 0.5–1.5s, skipped if `statusContainer.blocksMovement()`. Attack choice lives in `PlayState.pickEnemyAction` (reach-aware skill selection — see PlayState), throttled by `wantsToBasicAttack()` (independent `attackTimer`, interval 1.0–2.0s, early-out on `statusContainer.blocksAttack()`). **Status & death are uniformly wired through the combat pipeline:** `DamageSystem.apply` (or `Status.onApply`) feeds a `Status` into `StatusContainer`, and `render` checks `statusContainer.has(StatusType.FREEZE)` to apply the blue `FREEZE_TINT`. Death: `DamageSystem` calls `animController.enterDeath()`; `isDying()` exposes the fade and `isDead()` reads `isDeathComplete()` (state DEATH, alpha faded out — the fade length is the DEATH clip's own duration) — render/shadow/AI all early-out. The small HP number under the sprite is a separate `SceneRenderable` on `RenderLayer.OVERLAY` (alpha fades with the death animation). Dead enemies stay in the list — they become inert, no spawner cost.
- **`Combatant`** (in `systems/combat/`) — interface implemented by both `Player` and `Enemy`. Exposes `Health`, `Stats`, `Caster`, `GridPosition`, `GridMovement`, `Team`, `StatusContainer`, `AnimController`, the position shortcuts (`col/row`, `visualCol/Row`), the action gates (`canAct`, `canStartAttack`, `canStartCast`, `canUse(skill)`), `isAlive/isDead/isInputLocked`, and `hittableAt(col, row)` (move-tween i-frames). There are no lifecycle callbacks — the damage pipeline drives `enterHurt()`/`enterDeath()` on the `AnimController`. Every `SkillInstance`, every `Status`, and every `BattleState` helper operates on `Combatant` so the same code targets either team.
- **`Team`** (in `components/`) — `PLAYER` / `ENEMY` enum read by `Caster`, by `ProjectileInstance` (for direction), and by `BattleState.opposingOnRow` (filter targets by opposite team).
- **`BattleVfx`** (interface) / **`ClashEffect`** — `BattleVfx` is `update + render + isAlive`. `ClashEffect` scales 0.6→1.6 and fades over 0.25s; `PlayState` culls when `!isAlive()`.
### Skills
- **`Skill`** — pure, immutable data: `id`, `displayName`, `description`, `icon`, `Shape` (enum: `PROJECTILE/BEAM/STRIKE/AURA/ZONE`), `Element`, `List<Effect>` (unmodifiable), `cooldown`, `manaCost`, `vfxTexture` (required for every shape **except** a particle-backed AURA — `heal`/`regen`/`power_up`/`magic_up` ship without one because their `vfx` particle list carries the visuals), optional `vfxAnimation` (`Animation<TextureRegion>` — when present, renderers prefer it over the static texture; this is how `ice_beam` animates) backed by an owned `vfxAnimationSheet` `Texture` so disposal is symmetric, optional `vfxTint` (hex color) and `zoneTexture` (dedicated ground-cloud art), an optional `List<VfxFactory> vfx` (named particle effects from the JSON `"vfx"` array, resolved via `Vfx.byName`), optional `ShapeConfig`, and two damage-scaling knobs: `powerScale` and `magicScale`. When `applyEffectsTo` resolves a `DAMAGE` effect, the actual damage rolled into `DamageEvent.amount` is `effect.value + round(stats.power * powerScale) + round(stats.magic * magicScale)`. The same `Skill` can spawn many simultaneous `SkillInstance`s. Constructors are private — build with `Skill.builder()....build()`. The builder validates required fields and throws `IllegalStateException` naming the offending field on `build()`.
- **`ShapeConfig` and its three impls** — marker interface + per-shape tuning records. `ProjectileConfig`: `straight(speed)` for laser-style movement, `lob(targetRange, arcHeight, zoneDuration, zoneTickInterval)` for arcing tosses that land after `LOB_FLIGHT_TIME` and plant a landing cloud with the given zone timing (JSON `zoneDuration`/`zoneTickInterval`, defaults 3.0s/0.5s); the `movementType` also picks the instance class: `STRAIGHT` → `ProjectileInstance`, `LOB` → `LobInstance` (branched in `SkillFactory`). `StrikeConfig`: `dashTiles`/`hitTiles` (loader defaults 1/1 — `flame_claw`'s "dash 1, rake 2"). `ZoneConfig`: `pull`/`duration`/`tickInterval` — note the loader defaults `duration` to **1.0s** when a `shapeConfig` block omits it; `ZoneInstance`'s 3.0s `DEFAULT_ACTIVE` applies only when the skill has no config at all. Add a new `ShapeConfig` impl when a shape grows tunable parameters.
- **`SkillInstance`** — abstract base for runtime executions. Tracks `combatant: Combatant` (firing entity), plus the convenience refs `caster: Caster` and `pos: GridPosition` pulled off the combatant. Snapshots origin tile (`originCol/originRow` from `pos` at construction), tracks `finished/lockTaken`. Methods: `acquireInputLock()` (via `caster.getInputLock()`), `releaseInputLock()`, `finish()`, abstract `update(delta, SkillContext)`, default no-op `render(RenderContext)`. **Stores neither context.** The single `applyEffectsTo(Combatant target, SkillContext ctx)` walks the skill's effects and routes through `ctx.damageSystem.apply` (DAMAGE — mixes in `powerScale`/`magicScale`), `.heal` (HEAL), or `target.getStatusContainer().apply(StatusFactory.create(...), ctx.triggerBus)` (APPLY_STATUS — rolls chance first). KNOCKBACK is parsed but currently a no-op stub.
- **`SkillFactory.create(Skill, Combatant)`** — single static switch on `Shape` returning the right `SkillInstance` subclass. Adding a new shape means adding an enum entry, a switch case, and a new `SkillInstance` subclass. No context is threaded in: an instance is built from its definition and caster alone, and first meets the simulation when it is ticked.
- **`SkillLibrary`** — global catalogue of every `Skill` the game knows about, and the owner of their GPU resources (icons, VFX textures, VFX animation sheets — all disposed by `SkillLibrary.dispose()`). `defaults()` loads from `assets/skills/skills.json` via `SkillLoader.load(...)`. The catalogue today is **seventeen** skills (the JSON is the source of truth; highlights below — `manaCost` is 1 unless noted):
    - `wind_strike` — STRIKE, 30 base dmg + `powerScale 0.5`, 2.0s cd
    - `fire_blast` — PROJECTILE/straight (8 u/s), 20 dmg + BURN (3/tick, 5s) @ 60%, 3.0s cd
    - `venom_bomb` — PROJECTILE/lob (range 2, arc 2.0), 12 dmg + POISON (3/tick, 6s) @ 100%; spawns a `ZoneInstance` "cloud" on landing, 3.5s cd
    - `ice_beam` — BEAM, 25 dmg **+ FREEZE 2.0s @ 100% chance**, 4.0s cd, mana 2; uses an `Animation<TextureRegion>` sliced from `skills/animations/icebeam_spritesheet.png` (0.1s frame time)
    - `frost_trap` — ZONE/Ice (duration 5.0), 5 dmg per tick + FREEZE 3.0s @ 100%, 3.5s cd, mana 2
    - `heal` — AURA, 15 HP instant heal on entering ACTIVE, 5.0s cd, mana 2
    - `regen` — AURA, applies REGEN status (6 HP every 0.5s for 4.0s) on entering ACTIVE, 5.0s cd
    - `shield` — AURA, applies SHIELD status (blocks the next incoming hit; expires after 6.0s if unused), 4.0s cd
    - `wind_slash` — PROJECTILE/straight (12 u/s), 5 dmg, 0.5s cd, element NONE. Held in `Caster.basicAttack` by default; **not** added to the player's deck, so it never appears in `drawHand`.
    - `power_up` / `magic_up` — AURA buffs, 10s duration, 12.0s cd (the "triple power/magic" lives in `PowerUpStatus`/`MagicUpStatus`, not the JSON)
    - `flame_claw` — STRIKE/Fire, 22 dmg + `powerScale 0.6`, BURN (2/tick, 5s) @ 100%, 3.0s cd; `StrikeConfig` dash 1, rake 2
    - `thunder` — BEAM/Lightning, 28 dmg + `magicScale 0.7`, STUN 1.0s @ 50%, 4.5s cd, mana 2
    - `void_pull` — ZONE/Dark (pull, 6s duration, 1.0s tick, 6 dmg), mana 2
    - `dark_blast` — PROJECTILE/straight, Dark, 18 dmg + `magicScale 0.8` / `powerScale 0.1`, no status, 3.0s cd
    - `flame_torrent` — BEAM/Fire, 16 dmg + `magicScale 0.6`, BURN @ 15% chance, 5.0s cd, mana 2
    - `electro_ball` — PROJECTILE/lob (range 2, arc 2.0), Lightning, 10 dmg + STUN 1.5s @ 35%; landing zone lasts 3s, re-rolling the stun each 1s tick, 6.0s cd, mana 2
  The library does **not** hand-draw — that's the deck's job. `PlayerProfile` seeds the run's deck once with the six-skill starter set (`wind_strike`, `fire_blast`, `heal`, `ice_beam`, `shield`, `electro_ball`) and assigns `wind_slash` as the basic attack; the rest of the catalogue is the reward pool `RewardOffer.skillOffer` draws from (3 unowned skills per win).
- **`SkillDeck`** — per-caster standalone container of `Skill` references plus a private `SkillCooldowns`. Owned by a `Caster` (see Components). Methods:
    - `add(Skill)` / `remove(Skill)` / `contains(Skill)` / `all()` — membership; backed by a `LinkedHashSet<Skill>` so iteration order is stable for future inventory UIs (`drawHand` shuffles anyway).
    - `update(delta)` / `onUsed(Skill)` / `isOnCooldown(Skill)` / `remainingFor(Skill)` / `clearCooldowns()` — thin facade over the private `SkillCooldowns`.
    - `available()` — deck skills not currently on cooldown.
    - `drawHand(n, SkillSlots slots)` — eligible (off-cooldown + not in `slots`), shuffled, sliced to `n`. The deck has **no** back-reference to its caster; callers pass `SkillSlots` explicitly.
- **`SkillLoader`** — parses `skills.json` (top-level array) via libGDX's `JsonReader`/`JsonValue`. Each entry maps directly onto `Skill.builder()` setters; `effects` is a polymorphic list discriminated by `type` (`DAMAGE`/`HEAL`/`APPLY_STATUS`/`KNOCKBACK` — matching `EffectType`). `APPLY_STATUS` entries carry `statusType` (matching `StatusType`), `duration`, optional `chance` (default 100), and optional `value` (default 0, becomes the `dotMag` for DoT/HoT statuses). `shapeConfig.movementType` (`STRAIGHT`/`LOB`) dispatches to the existing `ProjectileConfig.straight(...)`/`.lob(...)` factories; `vfxAnimation` carries `spritesheet`, `frameWidth`, `frameHeight`, `frameDuration`, and optional `loop` (default false = play once and hold the last frame; true = cycle, e.g. `flame_torrent`'s churning stream); `powerScale`/`magicScale` are optional (default 0). Missing/malformed fields throw `IllegalStateException` naming the skill id and field path — no silent skipping.
- **`SkillCooldowns`** — `Map<String, Float>` remaining time. `update`, `onUsed`, `isOnCooldown`, `remainingFor`, `clear`. Lives inside a `SkillDeck` (one per caster); not exposed directly anywhere else. Ticked via `<entity>.update → caster.update → deck.update`.
- **`ChargeMeter`** — **dormant.** Formerly gated the staging menu (fill over ~5s, `consume()` on confirm); replaced by the `ManaPool` economy. The class (and `ChargeBarHud`) stay in the repo unreferenced for easy revival.
- **`Skill.manaCost`** — int, parsed by `SkillLoader` (`node.getInt("manaCost", 1)` — the default is 1 so a skill nobody costed is never free). Paid at staging time, not at fire time; the basic attack never enters the hand so its cost is never read.
- **`StrikeInstance`** — Phases: `DASH_FORWARD` (0.10s) → `HIT` (0.20s) → `DASH_BACK` (0.10s) → `DONE`. **Team-aware**: `dir = +1` for PLAYER, `-1` for ENEMY, applied to both the dash and the hit tiles. Acquires the caster's `InputLock`, dashes `dashTiles * dir` via `ctx.movementSystem.forceGridTeleport` (clamped only to the grid edge), spawns a `ClashEffect` (using the skill's own VFX texture) on the target tile (`hitTiles * dir` past the dash), looks up the target via `ctx.combatantAt(targetCol, row)` and applies effects if it isn't the caster's own team, then snaps back. Dash/hit reach comes from `StrikeConfig` (defaults 1/1). The VFX anchors to the *tile* (`ctx.projectedTileWorld` + `ctx.tileDepthScale`) so the flourish still lands even when no one's there to take it.
- **`ProjectileInstance`** — straight-flying projectiles only (lobs are `LobInstance`). **Team-aware**: `dir = caster.getTeam() == PLAYER ? +1 : -1`, applied to spawn-offset, velocity sign, grid-exit edge, sprite horizontal flip, and target lookup. Position is `colPos`, a **continuous column coordinate** — not a screen coordinate. Spawns one tile ahead of the origin, row-locked so a mid-step caster can't skew the trajectory, and travels `colsPerSecond = config.speed / 1.25` (definitions keep their authored world-unit speeds, converted once against the legacy 1.25-wide panel). Finishes past `COLS - 0.5` or `-0.5`, symmetric at both edges. The hit test is `Math.round(colPos)` then `ctx.battleState.combatantAt(col, row)` — the same lookup every other shape uses, and now equal on every row (it used to be depth-scaled, so far rows had narrower hit windows). A closer target soaks the hit so anyone behind survives. Same code handles either team because the lookup is team-relative.
- **`LobInstance`** — arcing projectile, split out of `ProjectileInstance` so straight-flight and parabolic code don't share a class. Parabolic arc from caster to `originCol + targetRange * dir` over `LOB_FLIGHT_TIME` (0.50s); on landing applies damage via `ctx.combatantAt(landCol, row)` (skipping same-team targets) — only the combatant standing on the landing tile takes the hit. Then spawns a synthetic `ZoneInstance` "cloud" via `ctx.combatSystem.spawn(...)` that inherits the parent skill's effects, tint, and particle `vfx` list, with zone timing from `ProjectileConfig.zoneDuration/zoneTickInterval`. The cloud's sprite is the skill's optional top-level `zoneTexture` (a dedicated ground-effect image, e.g. `electro_ball` → `effects/electro_zone.png`) falling back to the projectile's `vfxTexture` when absent (venom_bomb's glob doubles as its cloud). Lobs never participate in projectile clashes. LOB-from-enemy is latent (no enemy fires LOB skills today).
  Neither projectile class acquires `InputLock` — the caster keeps playing while the shot flies. Sprite size is resolved lazily from `ctx.battlefield` on the first update tick (no dependence on the caster's own sprite).
- **`BeamInstance`** — Phases: `CHARGE` (0.20s) → `FIRE` (0.70s) → `FADE` (0.25s) → `DONE`. Acquires `InputLock` for the windup; releases at the start of `FADE`. On entering `FIRE` it **pierces every opposing combatant** on the caster's row past `originCol` via `ctx.opposingOnRow(combatant, row)` (one application each, guarded by the `hitApplied` flag so the loop runs exactly once per fire). Render: if `Skill.vfxAnimation` is present (e.g. `ice_beam`'s sprite-sheet) the beam draws the current `Animation` frame; otherwise it stretches the static `vfxTexture`. During `CHARGE` the beam extends out from the caster (`w = fullW * (phaseTime/CHARGE)`); during `FADE` the stream runs out — the near end recedes toward the pinned far edge while alpha eases out (`1 - t²`), so the beam dissipates downrange instead of cutting off.
- **`AuraInstance`** — Phases: `EXPAND` (0.20s) → `ACTIVE` (variable) → `FADE` (0.20s) → `DONE`. **Self-targeted**: on entering `ACTIVE` it calls `applyEffectsTo(combatant, ctx)` once — instant `HEAL`s apply immediately (`heal`), `APPLY_STATUS` effects attach a Status to the caster's container (`regen`, `shield`). The ACTIVE duration is data-driven: if the skill has any `APPLY_STATUS` effects, ACTIVE lasts as long as the longest status duration; otherwise it falls back to a default 3.0s. `shouldFade()` also returns true early when every status the skill applied has been removed (e.g. a Shield consumed by an incoming hit immediately fades the aura visual). Renders a scaled, pulsing sprite on the caster's tile. Fires `Trigger.ON_TICK` once on entering ACTIVE — the per-tick HoT/DoT cadence then lives inside the Status itself, not in the AuraInstance.
- **`ZoneInstance`** — Phases: `APPEAR` (0.15s) → `ACTIVE` (`ZoneConfig.duration`; 3.00s `DEFAULT_ACTIVE` only when the skill has no config — a `shapeConfig` block that omits `duration` gets the loader's 1.0s default) → `FADE` (0.25s) → `DONE`. A `pull` zone drags the target one tile toward its center each tick via `ctx.movementSystem.applyDisplacement` (guarded by `tilesOccupied` so units can't stack). Pinned to a target tile (defaults to `caster +1, sameRow`; can be overridden — that's how `ProjectileInstance` plants a cloud on its landing tile). Every `TICK_INTERVAL` (0.33s) it resolves the target via `ctx.combatantAt(targetCol, targetRow)`, skips same-team, and applies effects — so a target walking off the tile escapes subsequent ticks, and one walking on starts taking them. Reports `RenderLayer.GROUND` from its `SceneRenderable`, so it draws under entities (terrain feel).
- **`slots/`** — `SlotKey` (`X, Y, B`), `ButtonSlot` (LIFO `ArrayDeque<Skill>`, **unbounded** — the last skill staged sits on top and fires first), `SkillSlots` (`EnumMap<SlotKey, ButtonSlot>` + `contains(Skill)`). Capacity is a **shared pool**, not per-slot: `SkillSlots.BASE_CAPACITY = 6`, `isFull()` sums all three stacks against the mutable `slotCapacity`, and `PlayState` recomputes it each battle as `BASE_CAPACITY + traits.slotCapacityBonus()` (+2 per capacity trait). A `SkillSlots` instance lives on each `Caster` (accessed via `caster.getSlots()`) — not on `GameScreen`. Slots persist across `PlayState` ↔ `SkillSelectState` transitions; cancel restores from a snapshot taken on `onEnter()`.
- **`effects/Effect`** — immutable record with type, value, duration, chance, and statusType fields. Factory constructors: `damage(int)`, `heal(int)`, `applyStatus(StatusType, duration, chance, dotMag)`, `knockback(tiles)`. `SkillInstance.applyEffectsTo(Combatant, SkillContext)` walks the effect list and routes each entry through `DamageSystem` (DAMAGE — mixes in `powerScale*power + magicScale*magic`), `DamageSystem.heal` (HEAL), or `target.getStatusContainer().apply` (APPLY_STATUS — rolls chance first; status is built by `StatusFactory.create`). KNOCKBACK is parsed and stored but is a stub today.
- **`effects/EffectType`** — `DAMAGE, HEAL, APPLY_STATUS, KNOCKBACK`. Status-specific types (FREEZE/BURN/POISON/STUN/REGEN/SHIELD/POWER_UP/MAGIC_UP) live in `systems/combat/StatusType` and are carried inside an `APPLY_STATUS` effect via the `statusType` field.
- **`elements/Element`** — `NONE, FIRE, POISON, ICE, LIGHTNING, DARK`. Currently cosmetic — no element-vs-element resistance/weakness logic yet.
### Systems
- **`Encounter`** — one battle. Built by `GameScreen` via `Encounter.create(player, enemies, manaStats, particles)`; owns the `BattleState`, `MovementSystem`, `CombatSystem`, the per-enemy `EnemyAi` list, the per-battle `ManaPool`, and the `vfx` sink. The `TriggerBus` and `DamageSystem` are **private** — nothing outside has business publishing events or applying damage directly. Applies traits at construction (slot capacity absolute, `applyBattleHooks` onto the fresh bus).
    - `tick(delta)` — the whole per-frame simulation, in one call. A single tick suffices because libGDX runs `input()` before `update()`, so the loaded-burst release lands outside it.
    - `outcome()` — `ONGOING` / `VICTORY` / `DEFEAT`. Reports only; deciding what a result *means* for the run (progression, rewards, screens) is `PlayState`'s job.
    - `tryMove` / `tryCast` / `cast` / `loadSkill` / `releaseLoadedSkills` / `collectCoveredTiles` / `finish` / `resetStaging` — the action surface. `combat()` and `battleState()` are exposed rather than fully wrapped; delegating every method would be ceremony.
  Knows nothing about screens, cameras or the run — it is handed a player and a roster.
- **`BattleState`** — authoritative roster (`player`, `List<Enemy> enemies`) plus the grid lookups every skill uses. No rendering, no camera:
    - `combatantAt(col, row)` — first alive `Combatant` *hittable* on that tile (player checked first), or `null`. Routes through `Combatant.hittableAt`, so move-tween i-frames apply. Used by Strike/Zone/Lob/Projectile.
    - `opposingOnRow(attacker, row)` — fresh list of alive, hittable combatants on the row whose team differs from `attacker`. Used by Beam (pierce all). Works for either team because the filter is "opposite of attacker."
    - `tilesOccupied(col, row)` — reservation semantics: reads raw `getCol/getRow`, so a mover counts on its destination the instant a step starts. Used by `MovementSystem.tryGridStep` and the zone pull's stacking guard — never for hits.
- **`SkillContext`** (in `skills/`) — the sim-side dependencies handed to `SkillInstance.update` **per tick and never stored**: `battleState`, `damageSystem`, `triggerBus`, `movementSystem`, `combatSystem`, plus `particleEngine` and `vfxSink` (the two remaining presentation handles, both marked `ponytail:`). No projection, no camera, no `Battlefield` instance — tile geometry is reached through the static `Battlefield.floorX/floorZ`. Skills can therefore be exercised without a viewport.
- **`EnemyAi`** (in `systems/ai/`) — one per enemy, holding both halves of the placeholder AI: the move timer (random step every 0.5–1.5s) and the attack timer (every 1.0–2.0s). `pickAction` walks the deck for the first off-cooldown skill whose shape can currently reach the player (`canReachPlayer` — AURA always; STRIKE at exactly 2 columns; ZONE at 1; BEAM/straight-PROJECTILE same row toward the player; LOB at exactly `targetRange`), falling back to the basic attack. Fires through a `Predicate<Skill>` that returns whether the cast happened, so **the throttle only resets on a real cast** — a refused action is retried next frame rather than costing a turn. Slated for overhaul; the logic is kept here so the rewrite can lift it cleanly.
- **`CombatSystem`** — owns `List<SkillInstance> active`.
    - `spawn(instance)` adds to the active list (callable from anywhere with a `SkillContext`, including from inside another `SkillInstance.update`).
    - `tickStatuses(delta)` walks the player and all enemies and ticks each alive combatant's `StatusContainer` against the shared `damageSystem` + `triggerBus`. Run *before* `update(delta)` in the per-frame loop so DoT kills and buff expirations land before this frame's skill instances resolve.
    - `update(delta)` ticks every active instance over a snapshot index — instances spawned mid-tick join the list but won't be ticked until next frame. Between the per-instance update and the finished-cull, `resolveProjectileClashes()` walks `active` pairwise: opposing-team `ProjectileInstance`s on the same row whose continuous columns are within half a tile of each other both `finish()` and a `Vfx.impact` particle burst plays at the midpoint (`spawnClash`, lifted `IMPACT_HEIGHT` 0.35 off the floor). Lobs are excluded automatically — `LobInstance` is not a `ProjectileInstance`.
    - `collectCoveredTiles(sink)` — forwards each active instance's `coveredTiles(TileSink)` report; each shape derives its footprint from the same fields its hit logic uses (zone reports only during `APPEAR`, so a planted zone's glow is cast-time only). `PlayState` wires this to `BattlefieldDecor::glow` each frame — pull-based, so coverage is never stored and can't go stale.
    - `submitRenderables(worldRenderer)` — submits every active instance to the shared `WorldRenderer` (each instance picks its own `RenderLayer`; `ZoneInstance` goes to `GROUND` so zone tiles sit visually beneath sprites).
    - `loadSkill(combatant, skill)` / `resolveLoadedSkills(combatant)` — the hold-to-load path: queue skills on the `Caster` while the trigger is held, then fire the whole burst on release (`matchRecipe` stub reserved for combo fusions). `tryCast`/`cast` are the shared single-skill entries.
    - `finishAll()` — force-finishes every active instance (called by `checkBattleOver` on both win and loss so locks release and VFX stop cleanly).
    - `hasActive()` for future menu/pause logic.
- **`SpawnSystem`** — budget-based encounter builder. `spawnNext(level)` computes `budget = clamp(level + 1, …, MAX_BUDGET 10)` (level = `PlayerProfile.getProgressionLevel()`), where a tier-N monster costs N points; it enumerates every integer partition of the budget across the five tiers (memoized per budget), filters to `total ≤ MAX_ENEMIES = 3`, picks one partition uniformly, then draws each slot uniformly from that tier's pool in the `SpawnTable`. Placement is sequential from `(COLS-1, 0)`, stepping rows and wrapping columns inward. Each `Enemy` gets its `Stats`, deck skills, and basic attack from its `SpawnConfig` (unknown skill ids throw at load). The roster lives in `assets/spawns.json` — T1 skeleton/beastkin, T2 lycan/lionen, T3 undead_beastkin/lich, T4 fenrir/elder_lich, T5 eclipse_beast/lich_king — loaded once per session (`GameSession` owns the `SpawnTable`).
- **`GameEnvironment`** — the seeded procedural 3D scene that hosts the battlefield (dressed by a `CaveTheme`: textures, fog/ambient colors, light palette, crystal counts). `rebuild(long seed)` regenerates everything: walls/ceiling/floor are subdivided grids displaced by seeded value noise (`ValueNoise` fbm, analytic normals); the floor's displacement is multiplied by a smoothstep `flatMask` that is exactly 0 over the gameplay rect (battle grid + walkable area + doors), so panel projection and billboard grounding stay valid by construction. Crystal formations (pink-body/cyan-tip hex spires built flat-shaded by `hexSpire`) place as hero clusters at shuffled perimeter anchor spots plus lone/hanging spires, each spawn ray-tested against the fixed camera (`ridgeHidden`) so terrain never occludes a base, and clamped clear of the walls' displacement range. `floorHeight`/`ceilingHeight` reproduce the displaced grids exactly for placement. Three point lights snap to the first crystal clusters each rebuild (a fixed front fill keeps combatants readable); `update(delta)` breathes emissive + light intensity on a slow per-cluster pulse with a soft flicker. The overworld rebuilds with `CaveTheme.OVERWORLD_SEED` (guarded no-op at launch), each battle with a random seed (`PlayState` ctor, before `BattlefieldDecor`). `dispose()` releases owned `Model`s and the `ModelBatch`; theme textures are borrowed.

### Combat (systems/combat)
- **`Combatant`** — described above under Entities. Player and Enemy both implement it.
- **`DamageSystem`** — single entry point for HP mutation. `apply(DamageEvent)`: defense mitigation → `ON_DAMAGE_TAKEN_PRE` (shields zero damage here) → `Health.damage` + `animController.enterHurt()` → `ON_DAMAGE_TAKEN`/`ON_HIT_LAND` → on death, `ON_DEATH`/`ON_KILL` then `animController.enterDeath()`. `heal(HealEvent)`: `Health.heal` (capped at max, halved while the target has BURN) + `ON_HEAL`. No other code path mutates HP.
- **`TriggerBus`** — pub/sub keyed on the `Trigger` enum. `subscribe(trigger, combatant filter, listener)` returns a `Subscription` for cleanup; passing a non-null filter restricts the listener to events whose `combatant` matches. `fire(TriggerEvent)` snapshots the bucket before dispatch so listeners may unsubscribe mid-fire.
- **`Trigger`** — `ON_HIT_LAND`, `ON_DAMAGE_TAKEN_PRE`, `ON_DAMAGE_TAKEN`, `ON_HEAL`, `ON_DEATH`, `ON_KILL`, `ON_TICK`. Payload type is documented on `TriggerEvent` and is part of the contract, not the type system (events are `Object`).
- **`Status` / `StatusContainer` / `StatusFactory`** — described in detail under "Combat & status pipeline." `Status` is the base; eight concrete subclasses live under `systems/combat/status/`:
    - `FreezeStatus` — blocks movement + attack + casting; rendered as blue sprite tint via `StatusContainer.has(FREEZE)`.
    - `StunStatus` — blocks movement + attack only.
    - `BurnStatus(dmg)` — 0.5s tick DoT (also halves incoming heals while active — enforced in `DamageSystem.heal`).
    - `PoisonStatus(dmg)` — 1.0s tick DoT.
    - `RegenStatus(heal)` — 0.5s tick HoT.
    - `ShieldStatus` — subscribes to its owner's `ON_DAMAGE_TAKEN_PRE` in `onApply`; zeros the next incoming `ev.amount` and self-expires; `onExpire` unsubscribes.
    - `PowerUpStatus` / `MagicUpStatus` — triple the owner's power/magic for the duration.
- **`event/DamageEvent`** — mutable carrier (`source`, `target`, `amount`, `sourceTag: SKILL/STATUS/PANEL/UNKNOWN`, `originalSkill`). `amount` is intentionally mutable so `ON_DAMAGE_TAKEN_PRE` listeners (Shield, future parries) can rewrite it.
- **`event/HealEvent`** — `target` + mutable `amount`. Symmetric to DamageEvent for over-heal cap or future buff math.
- **`event/TriggerEvent`** — wrapper passed to listeners: `trigger`, `combatant` (the subject — attacker for `ON_HIT_LAND/KILL`, target otherwise), `payload` (cast to the right event type per trigger).
### Components
The `components/` package is for ECS-style role components — entities compose them to opt into behaviors. Unlike leaf helpers in `util/`, components in this package may freely depend on `skills`.
- **`Caster`** — role component for entities that can stage and cast skills. Owns:
    - a final `Team team` (set in ctor; read by team-aware skill instances and exposed via `getTeam()`),
    - a final `SkillDeck deck` (skills the caster has access to + their cooldown timers),
    - a final `SkillSlots slots` (the X/Y/B staged loadout),
    - a final `InputLock inputLock` (held by skill instances during dash/cast — gates both entity movement and further skill firing),
    - a mutable `Skill basicAttack` (the skill fired by the dedicated `ATTACK_BASIC` button — swappable at runtime via `setBasicAttack(Skill)`),
    - a final `TraitsContainer traits` (the caster's owned passive traits — exposed via `getTraits()`; the player's persist across battles because the profile's Caster does, enemies start empty until spawn-config grants exist),
    - the **loaded-skill queue** for the hold-to-load burst mechanic (`CombatSystem.loadSkill` pushes, `resolveLoadedSkills` drains and fires on trigger release).
  Exposes `getTeam()` / `getDeck()` / `getSlots()` / `getInputLock()` / `getBasicAttack()` / `setBasicAttack(Skill)` and an `update(delta)` that ticks `deck.update(delta)`. Composed onto `Player` and `Enemy`; the entity's own `update` must call `caster.update(delta)` so cooldowns tick. The entity also delegates these getters directly so call sites stay clean (`player.getBasicAttack()` rather than `player.getCaster().getBasicAttack()`).
- **`GridPosition`** — logical-only position component for entities living on the panel grid: which tile (`col`, `row`) plus `depthScale` (perspective scale for the row). **Render position lives on `AnimController`** — the controller tweens between projected tile centers (`PlayState.tickEntities` pushes the projected target each frame). `setTile(col, row)` is unclamped — movement rules are enforced by `MovementSystem` (`tryGridStep` clamps to the entity's `GridBounds`; `forceGridTeleport` clamps only to the grid edge, which is how `StrikeInstance` drives an entity across territory).
- **`Health`** — `current` and `max` HP. Two mutators: `damage(int)` clamps to 0, `heal(int)` clamps to `max`. **Mutated only inside `systems/combat/DamageSystem`** — every other code path reads via `getCurrent()` / `getMax()`. Entities expose `getHp()` / `getMaxHp()` shortcuts that delegate here. Max HP is seeded from `Stats.vitality` at entity construction.
- **`Stats`** — `power`, `magic`, `vitality`, `defense`, `speed` (ints). Immutable today; set once at construction. `power`/`magic` are mixed into damage rolls via `Skill.powerScale` / `magicScale`; `vitality` is the initial max HP; `defense` feeds `DamageSystem.applyDefense` (percent reduction `raw * 100 / (100 + defense)`, floor 1); `speed` is parsed but not yet consumed. The player's block is fixed at `Stats(20, 10, 100, 10, 20)` on `PlayerProfile`; enemy blocks vary per monster via `SpawnConfig` (`spawns.json`) — see Known Gaps.
- **`ManaPool`** — the player's staging resource: `max` (10), `current` (float), `regenRate` (2/s). `update(delta)` regenerates toward max (ticked from `PlayState.tickMeters`); `spendMana(int)` refuses if insufficient; `drain()` zeroes (battle start + cancel penalty); `increaseMax`/`increaseRegenRate` are the future upgrade knobs. Lives on `PlayerProfile` (player-only — enemies cast for free), not on `Caster`.
- **`Team`** — `PLAYER` / `ENEMY` enum. Lives here (not in `entities/`) so `Caster` can hold one without `components/` having to import `entities/`.

### Util (small helpers)
- **`InputLock`** — owner-based lock. `lock(owner)` refuses if a different owner holds it; `unlock(owner)` is a no-op if you're not the holder. Owner is `Object` (not `SkillInstance`) so skill instances can hold the lock without `util` depending on `skills`. Identity comparison is all that matters.
- **`PanelGenerator`** — static factories that produce the `PanelType[][]` grid handed to `Battlefield`. Two presets: `generatePanels()` (flat blue/red split, used today) and `generateMixedPanels()` (sprinkles hazard tiles).

(The old `HitFlash` and `PositionSmoother` helpers were absorbed into `animation/AnimController` — hurt strobe and move tween respectively — and no longer exist.)
### UI
- **`ManaBarHud`** — the mana meter, tucked directly under the `LifeBarHud` in the top-left. Blue (`UiTheme.MANA`) fill; at full the frame gains a blue glow while the fill stays flat. Scene2D `Group` on the HUD stage; persistent bezels, `refresh(ManaPool)` updates the fill. (`ChargeBarHud` is its dormant predecessor, kept unreferenced.)
- **Top-left bar cluster** — `LifeBarHud`, `ManaBarHud`, and `StatusHud` no longer self-position; `GameScreen` stacks them in a single Scene2D `Table` (top-left anchored, `setRound(false)` for the world-unit stage, cells sized from each HUD's `BAR_*` constants with the `GAP_*` constants as row pads). Reordering or resizing the cluster means editing that one table.
- **`StatusHud`** — third row of the cluster (0.5 units tall): a translucent `SURF_LOW` tray holding one `StatusIndicator` (icon + remaining-seconds text underneath) per active status on the player, in `StatusType` order. Timer text is green (`UiTheme.BENEFIT`) for buffs, red (`UiTheme.DETRIMENT`) for debuffs — polarity comes from `StatusType.isBeneficial()`. Indicators are laid out by a `HorizontalGroup` (membership = shown); the whole tray fades in when the first status lands and fades out (contents frozen) when the last expires via Scene2D Actions — `GameScreen` now runs `hudStage.act(delta)` before `draw()`. Icons are placeholder skill PNGs (`skills/frost_trap.png` for FREEZE, etc.), loaded and disposed by the hud itself until dedicated status art exists.
- **`SlotsHud`** — bottom-left X/Y/B columns with stacked icons (top of column = top of stack, i.e. last staged / next to fire), placeholder for empty cells. A Scene2D `Group` on `GameScreen`'s HUD `Stage`, rebuilt per frame via `refresh(SkillSlots)` and drawn with the SDF bezels + shared `UiTheme` palette so it matches the staging overlay; the overlapping sliver compression stays hand-positioned inside the actor.
- **`BasicAttackHud`** — bottom-left icon one slot-gap to the right of the X/Y/B column, showing the skill held in `player.getBasicAttack()`. Renders a translucent black "cooldown veil" over the top portion of the icon when on cooldown — the veil shrinks downward as `deck.remainingFor(skill)` ticks toward 0, the standard MOBA-HUD cooldown sweep. Borrows the shared 1×1 white pixel from `GeneratedAssets` (constructor-injected; not owned).
- **`LifeBarHud`** — horizontal player HP bar, top row of the top-left cluster table. Fill ratio is `player.getHp() / player.getMaxHp()`; tint shifts green → yellow → red as HP drops (functional colors, deliberately outside `UiTheme`). Scene2D `Group` on the HUD stage; persistent bezels, `refresh(Player)` updates the fill.
- **`FpsHud`** — top-right frame-rate readout. Samples `Gdx.graphics.getFramesPerSecond()` every 0.25s (so the text doesn't flicker each frame).
- **`SkillSelectOverlay`** — card hand renderer used by `SkillSelectState`. `trayLayout(handSize)` squeezes chip width to fit the tray for any hand size (currently 6). Also owns the show/hide animations `SkillSelectState` drives (`confirmFlourish`, `onHide(callback)`) and the tuck mode's hidden presentation. The operator panel shows a gold `TRAITS n` count next to `SLOTS x/y`, and `buildTraitTray` renders the trait viewer modal when open: a glass panel of icon chips (4 per row, `SLOT_SIZE`-sized) under the operator panel with a name+description tooltip beneath, drawn last so it overlays the detail panel; the shared gliding gold cursor targets the focused panel/chip. Trait icons are `TraitLibrary`-owned (borrowed).
- **`UiUtil`** — shared world-unit-stage helpers, split out of `SkillSelectOverlay`: `newTable()` (a `Table` with `setRound(false)` — Tables round child geometry to whole units by default, which mangles the 16×9 stage; every table must come from here) and `genFont(generator, px, worldScale)` (FreeType font generated at pixel size, `setUseIntegerPositions(false)`, scaled to world units).
- **`RewardCardStyle`** — the style kit `RewardScreen` builds once and hands to every `RewardOption.buildContents`. Lives in `ui` deliberately: `UiTheme`, `BezelDrawable`, and `RoundedRectShader.draw` are package-private, so the kit consumes them internally and exposes only public scene2d types (`Label.LabelStyle` title/body/small, `Drawable` cardBg/cardBgSelected/statBox, the shared `pixel`). Owns and disposes its fonts + shader; never the pixel texture.
## Viewport & Coordinates
- World size: **16 × 9** world units (matches a 16:9 display).
- Battlefield occupies roughly `10 × 4` world units, placed at `(3, 1)`.

The `SKILL_X/Y/B` actions are dual-purpose by state: in `PlayState` they fire the front of the slot, in `SkillSelectState` they assign the highlighted hand card. In `PlayState`, holding `TRIGGER_RIGHT` (E / R2) while pressing a slot key *loads* the skill instead of firing it; releasing the trigger fires every loaded skill at once. Gamepad cancel is on Back rather than B so pressing B inside the menu doesn't double-fire (assign + cancel). `SKILL_SELECT_CONFIRM` (Enter / A) is reused by `GameOverScreen` for the post-battle restart so no new bindings were needed.
## Skill Flow (MVP)
1. Mana starts at 0 each battle and regenerates at 2/s toward max 10 (frozen while the menu is open).
2. Hold Q+E (or L2+R2) any time → `GameScreen` flips to `SkillSelectState`, world freezes, hand of 6 drawn.
3. ←/→ to move the cursor; 1/2/3 (or X/Y/B) to assign the highlighted card to that slot — refused if its `manaCost` doesn't fit in remaining mana. Slots that were already loaded persist (and re-stage free — prepaid); the menu is "top up," not "rebuild."
4. Backspace (or L1) undoes the most recent assignment (LIFO — refunds its pending cost unless it was prepaid); Tab (or R1) tucks the overlay away to peek at the frozen field.
5. Enter to confirm (spends the summed cost of newly staged skills, returns to `PlayState`) or Esc/Back to cancel (slots restored from snapshot, **entire mana pool forfeited**). Both play a short exit animation.
6. In play, 1/2/3 (or X/Y/B) fires the front of that slot via `SkillFactory.create()` → `CombatSystem.spawn()`. The skill's cooldown starts. Holding E (or R2) while pressing slot keys *loads* skills instead; releasing fires the whole burst at once.

The basic attack lives outside this flow: pressing **J** (or **A**) at any time fires `player.getBasicAttack()` through the same `SkillFactory` → `CombatSystem` pipeline, gated by `getDeck().isOnCooldown(skill)`. No mana, no staging — that's why the basic-attack skill is intentionally kept out of the deck (so it never appears in the staging hand).

## Battle End Flow
1. `PlayState.checkBattleOver` (called each frame after `combatSystem.update`) reads `allEnemiesDead()` (every entry in `enemies` has finished its death-clip fade) and `!player.isAlive()`.
2. On win, each enemy's death fade plays first (`isDying`) — armed by `DamageSystem` calling `animController.enterDeath()` when HP hits 0; the fade length is the DEATH clip's own duration. After every enemy's `isDead()` (`isDeathComplete()`) flips true, `combatSystem.finishAll()` + `progressPlayer()` + `resetStaging()` run, then the offer queue is built: `RewardOffer.skillOffer(session)` (up to 3 unowned skills) followed by `RewardOffer.traitOffer(session)` (up to 3 unowned traits), each skipped when null. The transition fires via `Main.setScreen(new RewardScreen(game, offers))` — or straight to `OverworldScreen` when both pools are drained.
3. `RewardScreen` walks its offer queue: pick (apply to the deck / the caster's traits) or skip each offer, then `Main.setScreen(new OverworldScreen(...))`. A future evolution unlock appends an `evolutionOffer` to the same queue.
4. On loss, transition to `GameOverScreen(LOST)` is immediate (after `combatSystem.finishAll()` + `resetStaging()`) — the player's `enterDeath()` fires like anyone else's, but `checkBattleOver` reads `!player.isAlive()` the same frame, so the fade never plays (see Known Gaps).
5. `Main.setScreen` swaps screens and queues the predecessor's `dispose()` for the next frame via `postRunnable`.
6. `GameOverScreen` shows the result + restart hint; pressing **Enter** or **A** calls `Main.setScreen(new GameScreen(...))`, which in turn disposes the spent `GameOverScreen` — yielding a fully fresh battle every restart.
## Design Rationale
- **Mana prices the staging, cooldowns gate the hand.** Two coexisting systems with different jobs: `ManaPool` controls *how much* you can stage (paid on confirm; cancel forfeits the pool, so opening the menu is a commitment), per-skill cooldowns control which skills are *available* to stage or fire. Enemies bypass mana entirely — it's a player-economy mechanic, which is why the pool lives on `PlayerProfile` rather than `Caster`.
- **Slots persist across menu opens** (Battle Network "custom screen" feel).
- **Snapshot/restore on cancel** rather than journaling individual assigns. Simpler and player-indistinguishable.
- **`InputLock` owner is `Object`** so `util/` stays a leaf package — a `SkillInstance` can hold the lock without `util` depending on `skills`. Identity comparison is all that matters.
- **Per-caster state lives on `Caster`, not `GameScreen`.** `SkillDeck` (which owns its own `SkillCooldowns`) and `SkillSlots` are properties of *this* casting entity. Cooldowns are the player's, not the battle's; the same applies to the staged loadout. `GameScreen` keeps only what's truly battle-global: the HUDs and a borrowed reference to the profile's mana pool.
- **`SkillDeck` has no caster back-reference.** Membership + cooldowns are intrinsic to the deck, but anything that needs to filter by slots (like `drawHand`) takes them as a parameter — keeps `SkillDeck` a standalone data structure and avoids the `Caster ↔ SkillDeck` loop.
- **`MovementSystem` is the single owner of *all* position writes — grid and free.** Grid methods take a `Combatant`: `tryGridStep(Combatant, Direction)` (input/AI — honors input-lock + movement-blocking status, clamps to the entity's `GridBounds`), `forceGridTeleport(Combatant, col, row)` (skill dashes/teleports — clamps only to the global grid edge, which is how a Strike's HIT phase legally enters enemy territory), and `applyDisplacement(Combatant, tiles, Direction)` (the named home for knockback/pull). The free branch takes a `FreePosition`: `applyFreeInput(FreePosition, dx, dy, delta)` (overworld avatar — integrates by speed, clamps to room bounds). The *mode* lives in which method the scene calls, not in a flag — so the overworld is a localized addition, not a re-architecture. `GridPosition.setTile` / `FreePosition.set` stay public but are, by convention, called only from here.
- **One-shot VFX are mostly particles now.** Projectile clashes and impact flourishes play named `Vfx` effects through the shared `ParticleEngine`; `ClashEffect` (scale+fade over a short lifetime) survives as `StrikeInstance`'s hit flourish, drawn with the skill's own VFX texture. Per-skill VFX textures live on `Skill.vfxTexture` — required except for particle-backed auras, whose `vfx` list carries the visuals instead.
- **Hit resolution lives inside each `SkillInstance`, but all of it resolves in grid space through `BattleState`** (synchronous, fixed-timing). No shape does its own overlap math anymore — Strike/Zone/Lob ask `combatantAt`, Beam asks `opposingOnRow`, and the projectile rounds its continuous column first. Nothing in the tick reads the camera. Two deliberately different questions: *hittability* (`Combatant.hittableAt` — unhittable for the first half of a move tween, then hittable at the destination; a dodge input always beats an incoming hit) vs *occupancy* (`tilesOccupied` — destination reserved at step start so units can't stack).
- **HP only mutates through `DamageSystem`.** A single chokepoint means defense, shields, hit-flash, death-fade trigger, and the `ON_DAMAGE_TAKEN_PRE/ON_DAMAGE_TAKEN/ON_HIT_LAND/ON_DEATH/ON_KILL` fan-out are written once and impossible to bypass. The cost is paying one virtual call per hit; the win is that adding the next reactive effect is a `TriggerBus.subscribe(...)` call and nothing else — inside a new `Status` for timed effects, or a `TraitEffect.onBattleStart` body for permanent ones (lifesteal and on-kill heal ship as traits).
- **`Combatant` interface replaces concrete `Player`/`Enemy` references in the combat pipeline.** Every `SkillInstance`, every `Status`, and every `BattleState` lookup operates on `Combatant`. The same Strike or Beam code therefore aims at either team based on `combatant.getTeam()`. This is the layer that made multi-enemy and (eventually) PvP-style enemy casting cheap to add.
- **Statuses subscribe to triggers in `onApply`, unsubscribe in `onExpire`.** Reactive effects (Shield, future parry/thorns/lifesteal) are written as a `Status` subclass whose `onApply` calls `bus.subscribe(Trigger.X, owner, listener)` — the owner-filter on the bus restricts the listener to that combatant, and the returned `Subscription` is held in the status for `onExpire` to clean up. No global handler registries; status lifecycle and reactive listener lifecycle are the same lifetime.
- **`SkillFactory` takes a `Combatant`, not bare components.** `SkillFactory.create(Skill, Combatant)` — the instance pulls `caster`/`pos` off the combatant, but every downstream effect application targets `Combatant`s through `BattleState` helpers. Avoids the four-arg signature the old `(Skill, Caster, GridPosition)` form was sliding toward as new components arrived.
- **Child instances spawn via `ctx.combatSystem.spawn(...)`.** A `LobInstance` landing plants a `ZoneInstance` cloud this way. Avoid coupling instances directly — always go through the combat system so spawn order, layering, and reaping stay consistent.
- **Traits are permanent bus subscribers, not Statuses.** A trait's reactive behavior can't be a `Status`: `StatusContainer` holds one status per `StatusType` (two hook traits would collide) and `Status` lifetime is a duration countdown a permanent effect breaks. Instead the per-battle `TriggerBus`/`DamageSystem` are rebuilt each battle, so `PlayState` calls `TraitsContainer.applyBattleHooks(owner, bus, dmg)` for the player and every enemy right after building the context — subscriptions are subscribe-and-forget (the bus dies with the battle), slot capacity is recomputed absolute (`BASE_CAPACITY + bonus`, idempotent), and traits never touch `Stats` (deliberate design decision: no stat traits). `TraitEffect` is an enum with behavior bodies — values like Vampiric Edge's 10% are Java code, while `traits.json` carries only presentation (id/name/description/icon) plus the effect constant's name. Trait presence checks are `TraitsContainer.has(id)`. Innate evolution traits later: `Evolution` will carry trait *ids* (not references, avoiding a `registry ↔ traits` cycle) resolved through `session.traits` and added to the caster's container — every downstream path is already idempotent.
- **Reward options render themselves.** `RewardOption.buildContents(RewardCardStyle)` returns the option's own Scene2D card content — a `SkillRewardOption` lays out icon/name/stats/description; future evolution and trait options will look entirely different — while `RewardScreen` owns only the uniform format (framed cells, sizing, highlight, navigation). The polymorphism lives in the option so the screen never type-switches. Each `RewardOffer` is one *kind* of reward ("choose a skill"; later "choose an evolution"), and the screen chains a queue of offers — a win that unlocks an evolution appends a second offer, zero screen changes.
- **Screen disposal centralized in `Main.setScreen`** rather than per-screen `dispose()` calls after a transition. The previous self-dispose idiom (still visible in old libGDX tutorials) was unsafe whenever a heavy screen swapped itself out mid-render — it would free textures still in use further up the call stack. Deferring the dispose via `Gdx.app.postRunnable` makes every call site `Main.setScreen(...)`-and-done.

## Deferred Decisions / Tech Debt
Decisions deliberately parked, each with the shape of the real fix. Distinct from
*Known Gaps* below, which is unbuilt features — these are choices already made
that we may want to revisit. Code sites carry a `ponytail:` comment pointing here.

- **`AnimController` conflates pose with position.** It owns both the pose state machine (IDLE/ATTACK/HURT, arbitrated by priority + locking) and the entity's visual grid position, and the move tween is driven off the *pose* clock (`stateTime`, `current == MOVE`). So a pose transition refused by priority also refuses the position change. This caused a real desync bug: `MovementSystem.tryGridStep` commits the logical tile, then `enterMove` is refused while locked in ATTACK or HURT (~1s each, since only the IDLE clip exists to read a duration from), leaving the body stranded until the next accepted move snaps it forward. It was invisible before the combat refactor only because `PlayState` re-synced every entity's visual position every frame — a self-healing loop hiding the disagreement.
  **Patched (option A):** `enterMove` now always writes the tween targets and snaps to the destination when the pose is locked, reproducing the pre-refactor behaviour.
  **Real fix (option B):** give the position tween its own clock, independent of `stateTime` and `current`, so position always accepts and always tweens while the pose stays priority-arbitrated. Fold in the clobbered `duration` line in `update()` (the MOVE branch is dead — see *Known Gaps*) while there.
- **Presentation still leaks into `SkillContext`.** `particleEngine` and `vfxSink` are the last two rendering handles reachable from a tick. They are at least projection-free now — a skill names a *tile*, never a screen point — so the harm is bounded. The fix is the Godot pattern: instances expose events (`HitLanded`, `HitFlashRequested`) and the scene subscribes. Note the full Godot design (a view class per instance) is **not** worth porting — `render(RenderContext)` on the instance is already a three-line immediate-mode call, and a `Map<SkillInstance, SkillView>` would be machinery with no payoff in libGDX. Port the events, keep the render method.
- **Skill instances cannot be constructed without a GL context.** All five shapes call `new Sprite(def.getVfxTexture())` in their constructor, and a libGDX `Texture` needs GL. Combat logic is otherwise viewport-independent after the refactor, so lazy-initialising the sprite on first `render()` is all that stands between here and a headless test that ticks a projectile into an enemy. There is also no test source set — `core/src/` has only `main`, and no JUnit dependency.
- **Attack vs cast is discriminated by basic-attack identity.** `Combatant.canUse` picks the status gate with `skill == getCaster().getBasicAttack()` — attack if so, cast otherwise. Correct today and needs no new data, but it cannot express "this deck skill is a physical attack". When that's wanted, put the kind on `Skill` and switch on it.
- **Stun now blocks casting.** Making `blocksCasting()` live changed what `StunStatus` means: it never overrode the flag, so `blocksMovement` had been doing that job by accident. It now declares `blocksCasting() → true`, preserving prior behaviour. If a stun should leave casting open, that's a one-line revert — a design call, not a correctness one.
- **Mana economy is freshly changed and unplaytested.** Committing a staged loadout drains the whole bar; cancelling drains half. This inverts the previous balance, where cancelling cost everything and confirming cost only the staged total. Also `ManaStats.increaseMax` / `increaseRegenRate` still have **no callers** — they are the intended reward/trait hook and are now on the run-level object where such upgrades can actually persist.
- **Tick order diverges from the Godot port.** Here the loaded-burst release happens in `input()`, before the whole tick. In Godot it sits *between* `TickCombatants` and `TickAi`, which is why that port splits the tick into named phases at all. Godot's comment claims its order is the legacy ordering; it isn't quite. Pick one deliberately when the two are next reconciled.

## Known Gaps / Future Work
- **Overworld is a thin slice.** `OverworldScreen` gives free-roam movement in the bare cave and two door floor-rects that launch a battle, with `GameSession`/`PlayerProfile` persisting the deck across the round-trip. Spawn *content* now exists (`spawns.json` + `SpawnSystem`) but it's a global tier table keyed by `progressionLevel` — both doors launch the same `new GameScreen(game)` with no room identity. Still missing: overworld *props* (the floor-decoration counterpart to battle panels — `GameEnvironment` is ready for them via `addDecor`), doors as actual wall openings rather than floor zones, varied/connected rooms, a seamless (non-hard-swap) transition, HP/position persistence (the avatar respawns at the room origin every visit), and per-room encounter definitions.
- **Entity animation: only `IDLE` art exists.** The character animation system is fully wired — `AnimController`/`AnimSet`/`FrameClip`/`AnimState`/`AnimSheet` (see *Animation*), and the drive hooks all fire (`enterAttack` from Strike/Projectile/Lob/Beam/Aura instances, `enterHurt`/`enterDeath` from `DamageSystem`, `enterMove` from `MovementSystem`). What's missing is purely art + `AnimSheet` rows: every monster declares only `IDLE`, so all other states fall back to the idle strip. Two controller quirks to fix when the art lands: `AnimController.update` computes a MOVE-aware duration then unconditionally overwrites it (the MOVE branch is dead), and HURT is hardcoded to a 1.0s lock.
- **`KNOCKBACK` effect is parsed but unimplemented.** `Effect.knockback(tiles)` builds the right record and `EffectType.KNOCKBACK` ships through the loader, but `applyEffectsTo`'s switch leaves it as a no-op. The machinery is proven — `MovementSystem.applyDisplacement` already powers the zone pull — so the hook is one line in the `KNOCKBACK` case, with direction derived from `caster.getTeam()`.
- **Player stats are static.** Enemies now get per-monster stat blocks from `spawns.json`, but the player is still constructed with `Stats(20, 10, 100, 10, 20)` on `PlayerProfile`. `progressionLevel` only feeds the spawn budget — there's no level-up, gear, or stat growth for the player yet.
- **Movement has half i-frames; Strike's dash doesn't.** Grid steps grant i-frames for the first half of the move tween (`Combatant.hittableAt`), but a Strike's `forceGridTeleport` dash is instant and fully hittable. If dash invulnerability is wanted, the same `hittableAt` hook is the place — or a status checked by `DamageSystem.apply` via `ON_DAMAGE_TAKEN_PRE`.
- **Enemy AI: skills landed, movement didn't.** Enemies cast real deck skills via the reach-aware `pickEnemyAction`, but movement is still a blind random walk — no repositioning to get a skill into reach, no panel awareness, and `SkillSlots` staging is unused for enemies (they fire straight from the deck).
- **Player death is still abrupt.** `DamageSystem` calls the player's `enterDeath()` like anyone else's, but `checkBattleOver` reads `!player.isAlive()` the same frame, so the transition to `GameOverScreen` fires before the fade can play. Waiting on `isDeathComplete()` (as the win path does for enemies) would give a symmetric death beat.
- **No panel state transitions** (`NORMAL → CRACKED → BROKEN` on stand/leave).
- **Panel effects** (ICE slide, LAVA/POISON DoT, GRASS heal) are defined as `PanelType`s and have textures, but no behavioral hooks yet. `DamageEvent.Source.PANEL` is plumbed through specifically so panel-DoT will fan through `DamageSystem` once wired.
- **Encounters are budget-random, not designed.** `SpawnSystem` gives variety (tier partitions over a 10-monster roster), but there are no authored encounters, no per-room/per-door spawn definitions, and no waves.
- **3D camera is fixed.** `GameEnvironment` poses the camera once at construction (`cam.far` is 26, deliberately tight so the stock shader's `dist²/far²` fog is visible inside the room; the farthest corner is ≈21 units). Decor placement ray-tests against the pose via package-visible `SceneCamera.CAM_X/Y/Z`. No screen-shake hook yet — adding one means animating `cam3D.position`/`lookAt` and revisiting the placement ray tests. There is no projection cache to invalidate any more.
- **Housekeeping debt:** `ChargeMeter` + `ChargeBarHud` are a dead-code island referencing only each other (kept for possible revival); `DamageSystem` prints a debug line on every damage event (`System.out.println`); `GameOverScreen.Result.WON` is dead (wins route to `RewardScreen`); `Main.dispose()` skips `ParticleEngine`/`WorldRenderer`/`RenderContext` (harmless — they hold no GPU state).
- **AuraInstance fires `ON_TICK` exactly once** (on entering ACTIVE). The inline comment `"might need move to status onTick??"` flags this as a design question — today periodic application is the Status's job (`RegenStatus.onTick` heals every 0.5s), but if an aura needs a per-tick effect that *isn't* a Status, the trigger fire would need to repeat. Decide before the next reactive-on-ON_TICK status lands.
- **Rewards are skills + traits; evolutions still pending.** `SkillRewardOption`/`skillOffer` and `TraitRewardOption`/`traitOffer` both exist and chain in the post-win queue. Evolutions (the `registry/` evolution types are unwired) become the next sibling option class + offer factory; when they land, `Evolution` gains innate trait ids resolved through `session.traits`. Offers are always skippable today; a `skippable` flag waits for the first mandatory offer type. Enemy traits are wired (every Caster has a `TraitsContainer`, hooks apply for all combatants at battle start) but nothing grants them yet — that's spawn config's job.
- **Fusion system parked.** Earlier design explored shape+element fusion tables; explicitly out of scope until the existing shapes feel good. The hold-to-load burst mechanic already reserves the hook: `CombatSystem.resolveLoadedSkills` runs the loaded queue through a `matchRecipe` stub before firing. Once revisited, fusion becomes "given two `Skill`s + their `Shape`/`Element`, produce a third or modify a spawned `SkillInstance`."
- **Main menu is still text-only** — two `font.draw` lines with no art, no buttons, no controller support (tap-to-start only). A proper title screen with selectable entries is future work.
