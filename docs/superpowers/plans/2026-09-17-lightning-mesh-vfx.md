# Lightning Mesh VFX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **House rule for this repo:** the owner types the Java edits themselves and Claude reviews the diff. Treat the code blocks below as the reviewed target, not as something to paste blind.

**Goal:** Replace Thunder's flat beam sprite with real 3D lightning bolts — Blender meshes, generated textures, and a lifetime-driven GLSL shader — following Le Lu's Godot technique, ported to libGDX.

**Architecture:** Blender contributes only geometry (a jagged bolt plane, a floor mark, an open shockwave cylinder) exported as one OBJ with three named materials. Three grayscale textures are generated by a Pillow script. The effect itself is a fragment shader: UV-pan a bolt texture, then `smoothstep` it against a threshold that rises over the bolt's 0→1 lifetime so it thins and dies. Bolts are drawn as raw `MeshPart`s with the scene camera inside the `BILLBOARD` bucket, so they depth-sort with sprites and pass through the existing bloom.

**Tech Stack:** Blender 4.x (OBJ export), Python 3 + Pillow, libGDX 1.14 (`ObjLoader`, `MeshPart`, `ShaderProgram`), GLSL 1.20-compatible shaders.

**Spec:** This plan is its own design record. Reference video: [Godot 4 - 3D Electric Lightning Shader for beginners](https://www.youtube.com/watch?v=C5g3Zdvitg4) (Le Lu, 2024-03-10). Chapter map: 00:50 meshes, 04:53 textures, 07:53 shaders, 21:56 particle settings.

## Global Constraints

- Blender units = game world units. Coordinate contract: blender (x, y, z) → game (x, z, −y). OBJ export with "Y up, −Z forward" applies this for you.
- Combat is measured in grid space. Bolt positions come from `Battlefield.floorX(col)` / `Battlefield.floorZ(row)`; the camera is touched only inside `render`.
- Skill visuals never load on demand. New PNGs go under `assets/skills/sprites/` (preloaded from the manifest); the model is queued in `GameAssets.queueLoad`.
- Every new fragment shader is registered in `ShaderCheck.PAIRS` and compiled by `gradlew.bat lwjgl3:shaderCheck`.
- `Skill` names nothing visual. All of this lives in `skills/visuals/` and `render/`.
- Do not use `export_arena.py` for the VFX mesh: it overwrites authored UVs with planar world UVs.
- No new dependencies. `ObjLoader` ships with libGDX and `AssetManager` already routes `.obj` to it.
- Commit style: `area: what changed` (see `git log`). No trailers.

## Why the technique transfers

| Le Lu in Godot | Here |
|---|---|
| Three meshes in one OBJ, one material each | Same OBJ; `ObjLoader` yields one `NodePart` per material |
| Painted Photoshop textures | `tools/generate_lightning_textures.py` (Pillow, seeded) |
| Visual shader: UV pan, `smoothstep`, remap, HDR gradient | ~10 lines of GLSL in `assets/skills/shaders/` |
| Particle `COLOR` ramp hack to get a 0→1 lifetime | `u_life = age / LIFE` — we own the timeline |
| GPUParticles: amount 2, life 0.25 s, rotate-Y, scale 1–2, box spawn | One bolt per tile of the beam span, same numbers |
| `unshaded`, `cull_disabled` | Raw `MeshPart.render` with cull off, depth test off, no lighting |

## Task 1: Generate the three textures

**Files:**
- Create: `tools/generate_lightning_textures.py`
- Output: `assets/skills/sprites/lightning_bolt.png`, `lightning_wave.png`, `lightning_mark.png`

**Interfaces:**
- Produces: three grayscale-in-RGB PNGs. Only the red channel is read. `lightning_bolt.png` tiles vertically (V), `lightning_wave.png` tiles horizontally (U).

- [ ] **Step 1: Write the script**

```python
"""Generate the three lightning VFX textures Le Lu paints by hand.

    assets/skills/sprites/lightning_bolt.png   64x256, zigzag, tiles in V (bolt crawl)
    assets/skills/sprites/lightning_wave.png  256x64,  wind streaks, tiles in U (cylinder wrap)
    assets/skills/sprites/lightning_mark.png  128x128, soft blob (floor scorch)

Usage: python tools/generate_lightning_textures.py
"""
from __future__ import annotations

import random
from pathlib import Path

from PIL import Image, ImageChops, ImageDraw, ImageFilter

OUT = Path("assets") / "skills" / "sprites"
RNG = random.Random(7)


def _crop_middle_tile(canvas: Image.Image, w: int, h: int, axis: str) -> Image.Image:
    """Draw on a 3x canvas so blur wraps, then keep the middle tile."""
    return canvas.crop((0, h, w, 2 * h)) if axis == "v" else canvas.crop((w, 0, 2 * w, h))


def bolt(w: int = 64, h: int = 256) -> Image.Image:
    canvas = Image.new("L", (w, 3 * h), 0)
    draw = ImageDraw.Draw(canvas)
    # One zigzag path from centre-top to centre-bottom, repeated three times so it tiles.
    pts, x, y = [], w // 2, 0
    while y < h:
        y = min(h, y + RNG.randint(8, 22))
        x = w // 2 if y == h else max(6, min(w - 6, x + RNG.randint(-14, 14)))
        pts.append((x, y))
    path = [(w // 2, 0)] + pts
    for k in range(3):
        seg = [(px, py + k * h) for px, py in path]
        draw.line(seg, fill=255, width=2)
    halo = canvas.filter(ImageFilter.GaussianBlur(3)).point(lambda v: min(255, int(v * 1.6)))
    core = canvas.filter(ImageFilter.GaussianBlur(0.6))
    merged = ImageChops.lighter(core, halo.point(lambda v: int(v * 0.6)))
    return _crop_middle_tile(merged, w, h, "v")


def wave(w: int = 256, h: int = 64) -> Image.Image:
    canvas = Image.new("L", (3 * w, h), 0)
    draw = ImageDraw.Draw(canvas)
    for _ in range(90):
        x0 = RNG.randint(0, 3 * w)
        y0 = RNG.randint(4, h - 4)
        length = RNG.randint(10, 60)
        draw.line([(x0, y0), (x0 + length, y0)], fill=RNG.randint(90, 255), width=1)
    streaked = canvas.filter(ImageFilter.GaussianBlur(1.2))
    # copies wrapped by ±w keep the middle tile seamless
    for dx in (-w, w):
        streaked = ImageChops.lighter(streaked, ImageChops.offset(canvas, dx, 0).filter(ImageFilter.GaussianBlur(1.2)))
    return _crop_middle_tile(streaked, w, h, "u")


def mark(size: int = 128) -> Image.Image:
    img = Image.new("L", (size, size), 0)
    px = img.load()
    c = size / 2.0
    for y in range(size):
        for x in range(size):
            dx, dy = (x - c) / c, (y - c) / (c * 0.85)   # slightly squashed, like his liquify pass
            r = (dx * dx + dy * dy) ** 0.5
            px[x, y] = int(255 * max(0.0, 1.0 - r) ** 2)
    return img


def main() -> None:
    OUT.mkdir(parents=True, exist_ok=True)
    for name, img in (("lightning_bolt", bolt()), ("lightning_wave", wave()), ("lightning_mark", mark())):
        img.convert("RGB").save(OUT / f"{name}.png")
        print("wrote", OUT / f"{name}.png", img.size)

    # self-check: the bolt must tile in V — brightest column at the top and bottom rows is the centre
    b = bolt()
    w, h = b.size
    top = max(range(w), key=lambda x: b.getpixel((x, 0)))
    bot = max(range(w), key=lambda x: b.getpixel((x, h - 1)))
    assert abs(top - w // 2) <= 2 and abs(bot - w // 2) <= 2, (top, bot)


if __name__ == "__main__":
    main()
```

**Interfaces:**
- Produces uniforms: `u_projTrans` (mat4, camera combined), `u_world` (mat4, per bolt), `u_texture` (sampler, unit 0), `u_time` (seconds since this bolt spawned), `u_life` (0..1), `u_color` (vec3, may exceed 1.0).
- Attributes consumed: `a_position` (vec3), `a_texCoord0` (vec2). `a_normal` is present in the mesh and silently skipped.

- [ ] **Step 1: Vertex shader**

```glsl
// lightning_mesh.vert — raw MeshPart draws: camera * per-bolt world transform.
attribute vec3 a_position;
attribute vec2 a_texCoord0;

uniform mat4 u_projTrans;
uniform mat4 u_world;

varying vec2 v_uv;

void main() {
    v_uv = a_texCoord0;
    gl_Position = u_projTrans * u_world * vec4(a_position, 1.0);
}
```

- [ ] **Step 2: Bolt fragment**

This is the whole trick from 09:00–14:00 of the video: pan, threshold, raise the threshold over life.

```glsl
#ifdef GL_ES
precision mediump float;
#endif
varying vec2 v_uv;
uniform sampler2D u_texture;
uniform float u_time;    // seconds since this bolt spawned
uniform float u_life;    // 0..1 over the bolt's lifetime
uniform vec3  u_color;   // HDR-ish, e.g. (1.0, 2.0, 10.0)

void main() {
    vec2 uv = vec2(v_uv.x, v_uv.y - 2.0 * u_time);      // UV pan: the bolt crawls along itself
    float t = texture2D(u_texture, uv).r;
    float a = smoothstep(u_life * 0.7, 0.7, t);         // edge0 rises 0 -> 0.7: bolt thins, then vanishes
    gl_FragColor = vec4(u_color * a, a);                 // premultiplied alpha
}
```

The FBO is 8-bit, so `u_color * a` clamps: the core (a≈1) turns white and the fringe (a<1) stays deep blue. That is the white-hot-core-with-blue-edge look we want, and bloom picks up the clamped core.

- [ ] **Step 3: Wave fragment**

```glsl
#ifdef GL_ES
precision mediump float;
#endif
varying vec2 v_uv;
uniform sampler2D u_texture;
uniform float u_life;
uniform vec3  u_color;

void main() {
    vec2 uv = vec2(v_uv.x, v_uv.y - u_life);            // streaks rise over life
    float t = texture2D(u_texture, uv).r;
    float fade = (1.0 - v_uv.y) * (1.0 - u_life);       // soft top rim, dies with life
    float a = t * fade;
    gl_FragColor = vec4(u_color * a, 0.0);              // additive: alpha 0 under ONE / ONE_MINUS_SRC_ALPHA
}
```

- [ ] **Step 4: Mark fragment**

## Task 5: Bolt drawing helper + Thunder visual (lazy version: bolts only)

**Files:**
- Create: `core/src/main/java/com/silverignis/skills/visuals/draw/LightningBolts.java`
- Modify: `core/src/main/java/com/silverignis/skills/visuals/beam/ThunderVisual.java`

**Interfaces:**
- Consumes: `GameAssets.lightningVfx()`, `SkillShaders.mesh("lightning_bolt")`, `RenderContext.projTrans()`, `VisualState.nearCol/farCol/row/dir`.
- Produces: `LightningBolts.strike(VisualState)`, `update(float delta, boolean restrike)`, `render(RenderContext, VisualState)`.

Design points, so the code reads as intent:

- **One bolt per tile of the span**, staggered outward from the caster by 0.04 s, each living 0.25 s (Le Lu's lifetime). While the beam is `ACTIVE` a dead bolt re-rolls yaw and scale on its tile and strikes again, so the row crackles; in `RECOVERY` they die out.
- **Random yaw 0–360 and scale 1–2** per bolt: his "rotate Y" flag and "scale 1..2" particle settings.
- **Raw GL inside the batch:** `batch.end()` flushes the sprites, we draw, `batch.begin()` re-binds the batch shader and its blend state on the next flush. Depth test is off because the depth buffer was cleared for the 2D pass anyway. Cull is off because the bolt is a two-sided cross and the wave's normals point inward.
- **Viewport:** the 3D camera spans the whole window while the 2D pass runs inside the `FitViewport` rect. They coincide at 16:9 but not when letterboxed, so save `GL_VIEWPORT`, set it to the back buffer, draw, restore.

- [ ] **Step 1: LightningBolts**

```java
package com.silverignis.skills.visuals.draw;

import com.badlogic.gdx.Gdx;
import com.badlogic.gdx.graphics.GL20;
import com.badlogic.gdx.graphics.Texture;
import com.badlogic.gdx.graphics.g3d.Model;
import com.badlogic.gdx.graphics.g3d.model.MeshPart;
import com.badlogic.gdx.graphics.g3d.model.Node;
import com.badlogic.gdx.graphics.g3d.model.NodePart;
import com.badlogic.gdx.graphics.glutils.ShaderProgram;
import com.badlogic.gdx.math.MathUtils;
import com.badlogic.gdx.math.Matrix4;
import com.badlogic.gdx.math.Vector3;
import com.badlogic.gdx.utils.Array;
import com.badlogic.gdx.utils.BufferUtils;
import com.silverignis.entities.Battlefield;
import com.silverignis.render.RenderContext;
import com.silverignis.skills.visuals.SkillVisuals;
import com.silverignis.skills.visuals.VisualState;

import java.nio.IntBuffer;
import java.util.Iterator;

/** Row of 3D lightning strikes: one bolt mesh per tile, each living {@link #LIFE}
 *  seconds and re-rolling while the beam is active. Drawn as raw MeshParts with the
 *  scene camera from inside the BILLBOARD bucket so they sort with sprites and bloom. */
public final class LightningBolts {

    public static final float LIFE = 0.25f;
    private static final float STAGGER = 0.04f;
    private static final Vector3 COLOR = new Vector3(1f, 2f, 10f);   // clamps to white core, blue fringe

    private static final class Bolt { int col; float yaw, scale, age, delay; }

    private final Array<Bolt> bolts = new Array<>(false, 8);
    private final Matrix4 world = new Matrix4();
    private final IntBuffer savedViewport = BufferUtils.newIntBuffer(16);
    private final MeshPart boltPart;
    private final Texture boltTex;

    public LightningBolts() {
        Model model = SkillVisuals.assets.lightningVfx();
        boltPart = part(model, "bolt");
        boltTex = SkillVisuals.assets.texture("skills/sprites/lightning_bolt.png");
        boltTex.setWrap(Texture.TextureWrap.Repeat, Texture.TextureWrap.Repeat);   // UV pan needs wrap
    }

    static MeshPart part(Model model, String material) {
        for (Node n : model.nodes)
            for (NodePart np : n.parts)
                if (material.equals(np.material.id)) return np.meshPart;
        throw new IllegalStateException("lightning.obj has no material '" + material + "'");
    }

    /** One bolt per tile of the span, staggered outward from the caster. */
    public void strike(VisualState vs) {
        int step = vs.dir > 0 ? 1 : -1;
        int i = 0;
        for (int c = vs.nearCol; c != vs.farCol + step; c += step, i++) {
            Bolt b = new Bolt();
            b.col = c;
            b.delay = i * STAGGER;
            roll(b);
            bolts.add(b);
        }
    }

    private static void roll(Bolt b) {
        b.yaw = MathUtils.random(360f);
        b.scale = MathUtils.random(1f, 2f);
        b.age = 0f;
    }

    /** Age bolts. While {@code restrike}, a dead bolt re-rolls on its tile instead of vanishing. */
    public void update(float delta, boolean restrike) {
        for (Iterator<Bolt> it = bolts.iterator(); it.hasNext(); ) {
            Bolt b = it.next();
            if (b.delay > 0f) { b.delay -= delta; continue; }
            b.age += delta;
            if (b.age < LIFE) continue;
            if (restrike) roll(b); else it.remove();
        }
    }

    public void render(RenderContext rc, VisualState vs) {
        Matrix4 projTrans = rc.projTrans();
        if (bolts.isEmpty() || projTrans == null) return;
        ShaderProgram sh = rc.skillShaders.mesh("lightning_bolt");

        rc.batch.end();                                         // flush sprites; raw GL from here
        Gdx.gl.glGetIntegerv(GL20.GL_VIEWPORT, savedViewport);
        Gdx.gl.glViewport(0, 0, Gdx.graphics.getBackBufferWidth(), Gdx.graphics.getBackBufferHeight());
        Gdx.gl.glEnable(GL20.GL_BLEND);
        Gdx.gl.glBlendFunc(GL20.GL_ONE, GL20.GL_ONE_MINUS_SRC_ALPHA);   // premultiplied
        Gdx.gl.glDisable(GL20.GL_DEPTH_TEST);
        Gdx.gl.glDisable(GL20.GL_CULL_FACE);

        boltTex.bind(0);
        sh.bind();
        sh.setUniformMatrix("u_projTrans", projTrans);
        sh.setUniformi("u_texture", 0);
        sh.setUniformf("u_color", COLOR);
        for (Bolt b : bolts) {

    }
}
```

```java
import com.silverignis.skills.visuals.*;
import com.silverignis.skills.visuals.draw.*;

import com.silverignis.particles.Vfx;

/** Thunder: a row of 3D lightning strikes, one per tile, re-striking while the
 *  beam is active, with embers and crackling discharge coming off the ground. */
public final class ThunderVisual extends AbstractSkillVisual {

    private final LightningBolts bolts = new LightningBolts();
    private boolean striking;

    @Override
    protected void react(Trigger t, VisualState vs, ParticleEngine engine) {
        switch (t) {
            case CAST -> vs.pose.enterCast();
            case ACTIVE -> {
                striking = true;
                bolts.strike(vs);
                play(engine, Vfx.beamEmbers(Vfx.tint(vs.element), vs.dir),
                     BeamQuad.alongSpan(vs), BeamQuad.intensity(vs));
                play(engine, Vfx.crackle(vs.element),
                     BeamQuad.alongSpan(vs), BeamQuad.intensity(vs));
            }
            case RECOVERY -> { striking = false; vs.pose.enterIdle(); }
            default -> {}
        }
    }

    @Override
    public void update(float delta) { bolts.update(delta, striking); }

    @Override
    public void render(RenderContext rc, VisualState vs) {
        if (hasEnded()) return;
        bolts.render(rc, vs);
    }
}
```

## Risks and known gaps

- **`batch.end()` inside a `SceneRenderable.render`** is new. `WorldRenderer.flush` runs inside `PlayState`'s `batch.begin/end`, so end/begin mid-loop is legal, and `SpriteBatch.begin` re-binds its shader while `flush` re-applies blending. If a later visual draws wrong, this is the first suspect.
- **Letterboxing.** Fixed by the viewport save/restore; verify at a non-16:9 window size once.
- **HDR colour clamps** in the 8-bit VFX buffer. Intentional here (white core, blue fringe). If you ever want true HDR blue, the `VfxManager` needs a float framebuffer.
- **Per-cast `new LightningBolts()`** looks up the model and texture each cast. Both are `AssetManager` lookups, cheap; the shaders are compiled once in `SkillShaders`.
- **Enemy casts** run the same code with `dir = -1`; the stagger loop handles either direction.
- **Other lightning skills** (`arc_bolt`, `volt_lance`, `electro_ball`) could reuse `LightningBolts` with a one-tile span at the impact tile. Not in scope; it is a `strike`-style overload away.
